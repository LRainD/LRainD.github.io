# 1. 需求背景

## 1.1 问题描述

报名审核阶段接入「合规自查」后，风控预警结果弹窗当前只能**看**、不能**处置**，存在三个具体痛点：

1. **大模型误判无处纠正。** 「合规自查」中引入的大模型规则（如报名附件合规性深度审查）存在误判：分供商其实已在附件中补充有效期内的资质证书，模型因附件水印、扫描件文字缺失等原因判定为「不满足公告要求」。当前弹窗没有任何纠正入口，误判只能线下沟通、退回供应商重报，一个误判能把整单报名审核卡住半天。
2. **规则引擎与模型误判被混在一起处理。** 规则引擎（如资质等级匹配、负面清单命中）命中的是客观事实，不允许人工覆盖；而大模型规则是概率判断，需要人工兜底。两者当前在弹窗里没有任何区分，合规官无法判断"这一条到底能不能改"。
3. **反馈内容看不到。** 「反馈评价」列只能提交反馈（满意/不满意 + 问题描述 + 附件），但合规官看不到用户已经提交的反馈正文。而"用户已经反馈过这个问题"往往正是误判的关键证据，看不到就等于无法判断。

## 1.2 目标用户

| 角色 | 特征 | 在本功能中的诉求 |
|------|------|------------------|
| 合规官（如 jctest1） | 报名审核责任人，对合规结论负责 | 对模型误判做人工纠正，且纠正动作必须留痕、可审计 |
| 报名审核业务专家 | 复核供应商报名材料 | 想知道预警为什么响、用户是否已经解释过 |
| 采购经办人 | 组织本次采购 | 希望误判不要阻塞审批提交，但审批提交动作本身必须干净 |

## 1.3 业务目标

| 目标 | 指标 | 目标值 |
|------|------|--------|
| 误判处置闭环 | 从发现误判到风险状态变为「已解除」的操作步数 | ≤ 3 步（点击解除 → 填说明 → 确认） |
| 处置留痕率 | 解除动作带说明并记录操作人/时间的比例 | 100% |
| 审批链路安全 | 「提交审批」弹窗中出现的解除入口数量 | 0 |

# 2. 产品定位

## 2.1 产品定义

在风控预警结果弹窗中新增一个**右侧固定「操作」列**，让合规官在核查现场就能「解除模型误判」，把误判处置从线下沟通搬进系统内闭环。

## 2.2 核心价值

1. **可纠正**：仅对「合规自查 + 大模型规则」开放解除，人工兜底模型误判。
2. **有边界**：规则引擎命中、已解除、未命中、计算中一律不可解除，不满足条件时直接不展示「解除风险」按钮（不使用置灰态）。
3. **可审计**：解除必须填写说明（≤200 字），记录操作人与时间，随预警一并留存。
4. **不越权**：解除能力只在「右侧 AI 浮窗」核查入口出现，「提交审批」入口不展示，避免在审批链路上临时改结论。

## 2.3 产品差异化（与替代方案对比）

| 方案 | 描述 | 问题 |
|------|------|------|
| 现状：只能看 | 误判只能线下沟通、退回重报 | 流程被卡死，无留痕 |
| 替代方案 A：放开全部预警可解除 | 任何预警都能解除 | 规则引擎客观命中也能被推翻，合规风险不可控 |
| 替代方案 B：直接改规则阈值 | 调整模型判定阈值 | 治标不治本，个案误判无法覆盖 |
| **本方案** | 按「场景 + 规则类型 + 状态」三元组收敛解除权限，强制填写说明 | 既能纠正误判，又不破坏规则严肃性，且全程留痕 |

# 3. 用户故事

## 3.1 合规官纠正模型误判

> 作为【合规官】，
> 在【日常报名审核、打开风控预警结果弹窗】时，
> 为了【把大模型的误判纠正掉、让真正合规的供应商不被拦】，
> 需要【在弹窗内直接解除这条预警，并写明解除理由】。

**验收标准**

- 只有「检测场景」含「合规自查」**且**为「大模型」规则的预警行，才可点击「解除风险」。
- 点击后弹出解除弹窗，必须填写解除说明（非空，≤200 字），否则不能提交。
- 提交成功后该行「风险状态」变为「已解除」，该行不再展示「解除风险」按钮；顶部统计中「已解除」数量与「解除比例」同步刷新。

**实现口径**

- 预警弹窗通过入口开关控制「操作」列是否展示：核查入口展示，提交审批入口不展示。
- 可解除的判定：检测场景含「合规自查」、规则类型为大模型，且风险状态不为「未命中」「计算中」「已解除」。
- 解除后留存解除说明、解除人、解除时间三项信息。

## 3.2 采购经办人提交审批

> 作为【采购经办人】，
> 在【核查完成、点击「提交审批」】时，
> 为了【确保审批结论干净、不被人临时修改】，
> 需要【此时弹出的预警弹窗不出现任何解除入口】。

**验收标准**

- 「提交审批」入口打开的弹窗：**无**「操作」列，也**无**「初次判定数据」列。
- 该弹窗底部按钮为「提交审核」/「取消」，不含任何解除动作。

**实现口径**

- 两个入口分别控制「初次判定数据」列与「操作」列：核查入口两列都展示，提交审批入口两列都不展示。

| 预警弹窗-操作列 | 解除风险 | P0 | 仅「合规自查 + 大模型规则 + 未解除」展示该按钮，不满足条件不展示 |
| 解除风险弹窗 | 解除说明必填校验 | P0 | 空值拦截、200 字上限、字数统计 |

## 4.2 功能详情

### 4.2.1 「操作」列展示与固定

- 位置：表格最后一列，列宽 150px，表头文案「操作」。
- 固定在右侧：横向滚动时该列始终贴在容器右侧，并用 8px 内阴影与左侧内容做视觉分隔。
- 底色：单元格为白色、表头为浅灰色、行悬停与选中行为浅蓝色，保证滚动时内容不从列下透出。
- 列内仅一个「解除风险」按钮，为小号文字链接按钮，左对齐。
- 按钮按可点击条件展示，不满足条件时直接不渲染（不使用置灰态、不提供悬停提示），该列展示 `-`（与其余列占位规则一致）。

### 4.2.2 解除风险

**展示条件（四条同时满足才展示「解除风险」按钮）**

| 判定项 | 规则 | 不满足时 |
|--------|------|----------|
| 行状态 | 不为「未命中」「计算中」 | 不展示该按钮 |
| 行状态 | 不为「已解除」 | 不展示该按钮 |
| 检测场景 | 含「合规自查」 | 不展示该按钮 |
| 规则类型 | 为大模型规则 | 不展示该按钮 |

> 四个条件为「与」关系，任一不满足即不展示「解除风险」按钮，操作列展示占位符「-」。

**判定矩阵（含种子数据对应的演示覆盖）**

| 检测场景 | 规则类型 | 风险状态 | 操作列 |
|----------|----------|----------|--------|
| 合规自查、风控预警 | 大模型 | 未解除 | 展示「解除风险」 |
| 合规自查 | 规则引擎 | 未解除 | `-`（仅大模型可解除） |
| 风控预警 | 大模型 | 未解除 | `-`（非合规自查不可解除） |
| 合规自查 | 规则引擎 | 已解除 | `-`（该风险已解除） |
| 合规自查 | 规则引擎 / 大模型 | 未命中 / 计算中 | `-` |

**解除风险弹窗**

1. **解除说明**（必填）
   - 多行输入框，4 行高，最多 200 字，右下角实时字数统计。
   - 占位文案：请填写解除理由，例如：该分供商已补充上传有效期内的施工劳务资质证书，模型识别为误判，人工复核通过。
   - 空值提交：输入框转 error 态，下方红字「请填写解除说明，便于后续审计追溯」，弹窗不关闭。
   - 输入非空内容后错误提示立即消失。
2. **底部操作**：「取消」（关闭弹窗，已填内容丢弃）、「确认解除」。

**解除后的信息变更**

| 变更项 | 变更内容 |
|--------|----------|
| 风险状态 | 「未解除」→「已解除」（绿色） |
| 解除记录 | 写入解除说明、解除人（账号与角色）、解除时间 |
| 顶部统计 | 「已解除」+1、「未解除」-1、「解除比例」= 已解除 / 检测项总数，重新计算 |
| 该行操作列 | 「解除风险」不再展示（该风险已解除），操作列展示 `-` |
| 轻提示 | 弹窗关闭后出现「风险已解除」轻提示 |

### 4.2.3 入口差异控制

| 入口 | 触发方式 | 初次判定数据列 | 操作列 | 底部主按钮 |
|------|----------|----------------|--------|------------|
| 核查入口 | 右侧 AI 浮窗（数字合规官）点击「报名审核汇总」节点 | 展示 | **展示** | 确定 |
| 审批入口 | 页面右上「提交审批」 | 不展示 | **不展示** | 提交审核 |

- 业务口径：解除动作必须在**核查阶段**完成；一旦进入「提交审批」，代表结论已定稿，不允许在同一动作里临时修改合规结论。
- 实现口径：「初次判定数据」列与「操作」列由两个独立开关控制，页面按入口决定是否展示。

## 4.3 功能详细说明

### 4.3.1 风控预警结果弹窗（列表类 / 弹窗）

在报名审核汇总页之上以浮层形式展示本次合规检测的全部风险预警项，并提供逐项核查与风险解除能力。

#### 功能点说明

| 功能点 | 功能描述 | 操作方式 | 数据来源 |
|--------|----------|----------|----------|
| 统计条 | 展示检测总数、计算中、未命中、已解除、未解除数量与解除比例 | 自动计算 | 当前展示数据 |
| 预警列表 | 展示全部风险预警项，按状态严重程度排序 | 自动加载 | 预警数据 |
| 风险状态列 | 已解除（绿）/ 未解除（红加粗）/ 未命中（灰）/ 计算中（橙） | 只读 | 风险状态 |
| 解除风险 | 打开解除弹窗，填写说明后置为已解除 | 点击操作列按钮 | 风险状态 / 解除记录 |
| 反馈入口 | 提交满意/不满意评价与问题反馈 | 点击「反馈评价」列 | 用户输入 |

#### 信息项定义

| 信息项 | 是否必填 | 显示说明 | 取值范围 |
|--------|----------|----------|----------|
| 风险预警名称 | 是 | 每行预警的名称 | 1-60 字 |
| 检测场景 | 是 | 多场景用「、」连接 | 合规自查 / 风控预警，可组合 |
| 规则类型 | 是 | 大模型规则或规则引擎规则，决定能否解除 | 大模型 / 规则引擎 |
| 风险状态 | 是 | 行的当前状态 | 已解除 / 未解除 / 未命中 / 计算中 |
| 当前数据描述 | 否 | 当前检测到的数据情况 | - |
| 初次判定数据 | 否 | 首次检测的数据与结论，仅核查入口展示 | - |
| 解除记录 | 否 | 解除说明、解除人与解除时间 | 见下 |

**解除记录包含的信息**

| 信息项 | 说明 |
|--------|------|
| 解除说明 | 解除时填写的理由，1-200 字 |
| 解除人 | 执行解除的账号与角色 |
| 解除时间 | 解除的具体时间 |

#### 交互说明

- 加载逻辑：弹窗打开时按当前入口决定是否展示「初次判定数据」列与「操作」列，数据一次性渲染。
- 排序逻辑：按「未解除 → 已解除 → 未命中 → 计算中」排序，同状态内保持原始顺序，序号按排序后从 1 编号。
- 解除联动：确认解除后，行状态、操作列按钮展示状态、顶部统计三处同步刷新，无需关闭重开弹窗。
- 弹窗互斥：提交反馈弹窗与解除弹窗均为居中弹层，点击遮罩或 × 关闭；任一弹窗打开时不影响底层表格状态。

#### 异常处理

- 无预警数据：表格区域展示空态提示，操作列同步隐藏。
- 未命中/计算中行：不提供任何操作，整列占位 `-`，避免"看不出能不能点"。
- 解除说明为空：拦截提交，输入框标红并给出红字提示，弹窗保持打开。
- 解除说明超长：输入框限制 200 字，超出不可继续输入，字数统计实时反馈。

#### 性能要求

- 弹窗打开到表格可交互 ≤ 500ms（10 行量级）。
- 操作列固定不产生横向滚动抖动，滚动帧率 ≥ 50fps。
- 解除/反馈状态更新到界面刷新 ≤ 100ms（本地状态更新，无网络等待）。

### 4.3.2 解除风险弹窗（表单类 / 弹窗）

#### 页面概述

承载「解除风险」动作的二次确认表单，强制收集解除说明用于审计追溯。

#### 页面布局

```
+--------------------------------------------------+
| ▍解除风险                                    [×] |
+--------------------------------------------------+
|  * 解除说明                                       |
| +----------------------------------------------+ |
| | 请填写解除理由，例如：该分供商已补充上传有效期  | |
| | 内的施工劳务资质证书，模型识别为误判...        | |
| |                                    0/200      | |
| +----------------------------------------------+ |
|                               [取消] [确认解除]   |
+--------------------------------------------------+
```

#### 功能点说明

| 功能点 | 功能描述 | 操作方式 | 校验 |
|--------|----------|----------|------|
| 解除说明 | 必填文本域，200 字上限 | 键盘输入 | 非空 + ≤200 字 |
| 取消 | 关闭弹窗，丢弃已填说明 | 点击 | - |
| 确认解除 | 校验通过后写回状态并关闭 | 点击 | 同上 |

#### 输入项定义

| 信息项 | 是否必填 | 校验规则 | 显示说明 |
|--------|----------|----------|----------|
| 解除说明 | 是 | 去空格后非空，≤200 字 | 4 行文本域，带字数统计 |
| 错误提示 | - | - | 空值提交时展示红字错误 |

#### 交互说明

- 每次打开弹窗均重置说明与错误态，不复用上一次输入。
- 输入非空内容时，若当前为错误态则立即清除错误提示。
- 「取消」「×」「点击遮罩」三种关闭方式行为一致，均不保存。
- 确认成功后：写入解除记录、关闭弹窗、清空输入、出现「风险已解除」轻提示。

#### 异常处理

- 说明为空：红字「请填写解除说明，便于后续审计追溯」，弹窗不关闭，焦点留在文本域。
- 说明仅空格：按空值处理。
- 连续点击「确认解除」：首次确认成功后弹窗即关闭，不产生重复解除记录。

#### 性能要求

- 弹窗打开 ≤ 200ms，输入无卡顿。
- 确认提交到状态刷新 ≤ 100ms。

# 5. 用户旅程

**主旅程：合规官处置一条模型误判**

| 步骤 | 场景 | 用户动作 | 系统反馈 |
|------|------|----------|----------|
| 1 | 报名审核汇总页 | 打开右侧「数字合规官」浮窗 | 展示合规检测节点树 |
| 2 | 浮窗 | 点击「报名审核汇总」节点 | 打开风控预警结果弹窗（含初次判定数据、含操作列） |
| 3 | 弹窗 | 看到「报名附件是否满足公告要求」标红「未解除」 | 操作列「解除风险」可点 |
| 4 | 弹窗 | 判断为模型误判，点击「解除风险」 | 打开解除弹窗，仅需填写解除说明 |
| 5 | 解除弹窗 | 填写解除说明（如"证书已在附件第 3 页，模型未识别"） | 字数统计实时更新 |
| 6 | 解除弹窗 | 点击「确认解除」 | 弹窗关闭、出现「风险已解除」轻提示 |
| 7 | 预警弹窗 | 观察该行 | 风险状态变绿「已解除」，该行不再展示「解除风险」按钮，顶部「已解除 +1、解除比例刷新」 |
| 8 | 页面 | 点击「提交审批」 | 预警弹窗再次打开，**无操作列**，仅可确认提交 |

**分支旅程**

- 规则引擎命中项：合规官看不到「解除风险」按钮（不展示，无悬停提示）→ 走线下补充材料流程。
- 一般风控预警：看不到「解除风险」按钮（不展示，无悬停提示）→ 该风险不能在此处解除。

# 7. 非功能性需求

## 7.1 性能需求

- 弹窗数据渲染不引入额外网络请求（复用已加载的检测结果）。
- 固定列采用样式定位实现，不通过脚本监听滚动重复绘制。

## 7.2 可用性需求

- 弹窗宽度在 1440px 下可完整展示 10 列 + 固定「操作」列；更窄屏允许横向滚动，固定列仍可用。
- 解析/渲染失败时不影响页面主流程，弹窗可关闭。

## 7.3 安全需求

- 解除动作仅「合规官」角色可见可用。
- 解除说明与操作人必须落库，且不可被后续操作覆盖（一次解除一条记录）。
- 「提交审批」链路不得暴露解除入口，避免绕过审批。

## 7.4 数据统计需求

- 需按「场景 × 规则类型 × 解除人」留存解除明细，供合规审计抽查。
- 统计口径：解除比例 = 已解除数 / 检测项总数（含未命中、计算中）。

## 补充说明：操作列权限与展示规则

风控预警结果弹窗右侧固定「操作」列仅包含「解除风险」一个操作，按权限与可点击条件决定是否展示；不满足条件时直接不展示该按钮，不使用置灰态：

| 操作 | 采购经办人 | 合规官 | 展示条件 |
| --- | --- | --- | --- |
| 解除风险 | 不展示 | 展示 | 检测场景含「合规自查」、规则类型为大模型规则、且风险状态为「未解除」；任一条件不满足时不展示该按钮 |

说明：

- 「解除风险」属于合规官专属权限，采购经办人不可执行；经办人视角下该按钮不展示。
- 按钮不可展示时（如规则引擎行、非合规自查行、已解除行、未命中/计算中行），操作列展示占位符「-」。
- 操作列仅在右侧「数字合规官」AI 浮窗入口打开预警弹窗时展示；从提交审批入口打开时不展示操作列。
- 当前原型以合规官身份演示，未提供角色切换：按钮是否展示由场景、规则类型与风险状态决定。若需演示经办人视角，应隐藏「解除风险」，操作列全部展示「-」。
