# 1. 需求背景

## 1.1 问题描述

- 原有附件盖章方式为普通圆形单选，视觉权重低，供应商难以直观理解"电子签章更快"的价值，容易沿用纸质扫描件流程。
- "一键导入"入口与附件格式说明挤在同一区域，用户不易发现，导入能力使用率低。
- 导入完成后，页面直接堆出附件列表，用户不清楚导入结果是否正确、下一步该做什么，容易漏检就提交。

## 1.2 目标用户

- 供应商 / 投标方报名操作人（商务人员、资质管理员）
- 首次报名、不熟悉附件要求的新供应商

## 1.3 业务目标

- 提升电子签章的选择率，减少纸质流转
- 提升一键导入的发现率与确认率
- 让导入结果可见、可核对，降低因附件缺失导致的无效报名

# 2. 产品定位

## 2.1 本迭代定义

对报名信息弹窗"报名附件"区的体验优化：盖章方式卡片化、一键导入入口前置、导入后以文件组成部分呈现结果并给出核对建议。

## 2.2 核心价值

- **决策更直观**：两种盖章方式以卡片并列，优势文案直接可见
- **入口更聚焦**：一键导入独立成行，位于附件格式说明正下方
- **结果更可见**：导入完成后展示文件组成部分，替代"导入即结束"的黑盒体验

## 2.3 与迭代前的差异

| 维度 | 迭代前 | 迭代后（本期） |
|------|--------|----------------|
| 盖章方式 | 普通单选，仅名称 | 两张卡片，含推荐角标与时效说明，选中态高亮 |
| 一键导入入口 | 与附件说明同区域，易被忽略 | 位于格式说明下方独立展示，导入后隐藏 |
| 导入结果 | 直接改写附件列表，无结果说明 | 展示文件组成部分 + 导入完成反馈 |
| 核对引导 | 无 | 列表下方展示"建议：请先检测报名文件完善性，再提交报名" |
| 推荐附件标识 | 展示 AI 标识与推荐依据 | 已移除，展示样式与普通附件一致 |

# 3. 用户故事

## 3.1 选择附件盖章方式

作为【供应商报名人】，
在【上传报名附件前】场景下，
为了【快速判断哪种盖章方式更适合自己】，
需要【以卡片形式直观对比电子签章与纸质扫描件】。

- 验收标准：两张卡片左右平分占满整行，不展示字段名；电子签章带"推荐"角标与"最快10分钟完成"说明；整卡可点击，选中态清晰。
- 技术实现要点：卡片组件化，选中态由盖章方式状态驱动，切换不丢失各模式附件。

## 3.2 发现并使用一键导入

作为【供应商报名人】，
在【已选择电子签章】场景下，
为了【不逐个查找附件】，
需要【在附件格式说明下方直接看到一键导入入口】。

- 验收标准：入口位于格式说明正下方、与卡片左边缘对齐；点击后进入引导/导入流程；导入完成后入口隐藏。仅报名环节且存在文件组成时展示；无文件组成、纸质扫描件、投标/调价环节均不展示，附件区保持原状直接展示文件组成部分。
- 技术实现要点：入口展示条件为"报名环节 + 电子签章模式 + 存在文件组成 + 未完成导入"。

## 3.3 核对导入结果

作为【供应商报名人】，
在【完成一键导入】场景下，
为了【确认附件是否齐全再提交】，
需要【看到按文件组成展示的导入结果与核对建议】。

- 验收标准：导入后展示文件组成部分，包含各分类与附件；列表下方展示橙色建议文案；推荐附件不展示 AI 标识与推荐依据。
- 技术实现要点：确认带入时按文件组成追加附件并按文件 ID 去重，已完成导入标记驱动结果区与建议文案展示。

## 4.2 功能详情

- **卡片化**：不展示"附件盖章方式"字段名，两张卡片占满整行；电子签章为推荐项，说明"在线签署，最快10分钟完成，无需打印快递"；纸质扫描件说明"需打印、盖章、扫描上传，约1-2天"。
- **入口前置**：一键导入按钮位于附件格式说明下方，仅在电子签章模式且未完成导入时出现。
- **导入结果**：确认带入后展示文件组成部分（分类 + 附件），已有附件保留，推荐附件按 ID 去重追加。
- **反馈与引导**：导入完成展示绿色完成提示（约 3 秒），列表下方展示橙色建议文案。
- **样式统一**：推荐附件与普通附件展示一致，不再有 AI 标识与推荐依据。

# 4.3 功能详细说明

## 4.3.1 附件盖章方式卡片化

### 页面概述

将原有普通单选改造为两张并排卡片，强化电子签章的价值感知，降低选择成本。

### 页面布局

```
+--------------------------------------------------------------+
| ▍报名附件                                             [^]    |
|  +-----------------------------+  +------------------------+ |
|  | (•) 电子签章   [推荐]       |  | ( ) 纸质扫描件         | |
|  | 在线签署，最快10分钟完成，  |  | 需打印、盖章、扫描上传 | |
|  | 无需打印快递                |  | ，约1-2天              | |
|  +-----------------------------+  +------------------------+ |
|  *附件：大小限制：100M　支持格式：.pdf                        |
|        （电子签功能仅支持最多20个100M以内的pdf文件…）         |
|  [一键导入]                                                   |
+--------------------------------------------------------------+
```

### 功能点说明

| 功能点 | 功能描述 | 操作方式 | 数据来源 |
|--------|----------|----------|----------|
| 卡片布局 | 两张卡片左右平分，占满整行，不展示字段名 | - | - |
| 选项标题 | 电子签章 / 纸质扫描件，含单选圆点 | - | - |
| 推荐角标 | 电子签章标题右侧橙色"推荐"标签 | - | - |
| 优势说明 | 卡片下方展示该方式的时效与操作成本 | - | - |
| 选中态 | 橙色描边 + 浅橙底色 + 橙色单选点，说明文案变绿 | 点击卡片任意位置 | 本地状态 |
| 未选中态 | 浅灰描边白底、说明文案灰色，悬停描边变浅橙 | 悬停 | 本地状态 |

### 数据字段定义

| 字段名称 | 字段类型 | 显示说明 | 取值范围 |
|----------|----------|----------|----------|
| uploadMethod | Enum | 当前盖章方式 | `esign` / `scan` |
| esignDesc | String | 电子签章卡片说明 | 在线签署，最快10分钟完成，无需打印快递 |
| scanDesc | String | 纸质扫描件卡片说明 | 需打印、盖章、扫描上传，约1-2天 |
| recommended | Boolean | 是否展示"推荐"角标 | 电子签章为 true |

### 交互说明

- 整卡点击即可切换，点击单选圆点同样生效。
- 切换后下方附件格式说明、一键导入入口、附件列表同步刷新。
- 两种模式各自维护附件集合，来回切换互不覆盖。
- 卡片高度随文案自适应，两卡等高。

### 异常处理

- 未选择任何方式：仅展示两张卡片，不展示附件说明与附件列表。
- 文案过长：卡片内换行展示，不截断关键信息。

### 性能要求

- 切换方式后界面刷新 ≤ 200ms

## 4.3.2 一键导入入口下移与导入流程

### 页面概述

一键导入入口从与附件说明混排调整为独立一行，位于格式说明正下方；导入完成后入口隐藏。

### 展示范围

一键导入依赖"文件组成"作为导入目标，因此仅在**报名环节的附件区、且存在文件组成**时展示。

| 场景 | 是否展示一键导入 | 附件区表现 |
|------|------------------|------------|
| 报名环节 + 电子签章 + 有文件组成 + 未导入 | 展示 | 格式说明 → 一键导入 → 文件组成部分 → 核对建议 |
| 报名环节 + 电子签章 + 无文件组成 | 不展示 | 仅展示格式说明，不出现空的文件组成容器 |
| 报名环节 + 纸质扫描件 | 不展示 | 保持原状：格式说明 + 文件组成部分 |
| 投标 / 调价环节 | 不展示 | 保持原状：直接展示文件组成部分，无导入入口与导入反馈 |

说明：

- 一键导入按钮的展示前提是"有文件组成"，没有文件组成时不存在可导入的目标，不展示入口。
- 投标、调价环节不具备一键导入能力，附件区沿用原有样式：直接展示文件组成部分（分类标题、附件行、添加附件），不出现一键导入按钮、导入完成提示与核对建议文案。
- 没有一键导入按钮的场景下，附件区保持原状，不新增任何占位或说明，避免与原流程产生差异。

### 页面布局

```
迭代前：*附件：大小限制…  [一键导入]        ← 入口与说明混排，易忽略
迭代后：
  *附件：大小限制：100M　支持格式：.pdf
         （电子签功能仅支持…）
  [一键导入]                               ← 独立成行，与卡片左边缘对齐
  +--------------------------------------+
  | 文件组成部分（导入确认后展示）        |
  +--------------------------------------+
```

### 功能点说明

| 功能点 | 功能描述 | 操作方式 | 数据来源 |
|--------|----------|----------|----------|
| 入口展示 | 仅报名环节、电子签章模式、存在文件组成且未完成导入时展示，位于格式说明下方 | 自动展示 | 本地状态 |
| 入口隐藏 | 完成导入后不再展示，避免重复导入 | 自动 | 本地状态 |
| 无入口降级 | 无文件组成、纸质扫描件、投标/调价环节不展示入口，附件区保持原状直接展示文件组成部分 | 自动 | 本地状态 |
| 引导浮层 | 切换到电子签章、未导入且未勾选"不再提示"时指向一键导入按钮 | 自动弹出 | 本地状态 |
| 不再提示 | 勾选后不再自动弹出引导 | 勾选复选框 | 本地状态 |
| 导入弹窗 | 两步：开始一键导入 → 推荐预览 | 点击按钮 | 推荐接口 |
| 确认带入 | 预览结果写入页面附件并关闭弹窗 | 点击"确认带入页面" | 预览数据 |

### 数据字段定义

| 字段名称 | 字段类型 | 显示说明 |
|----------|----------|----------|
| hasImportedEsign | Boolean | 是否已完成一键导入，驱动入口隐藏与结果展示 |
| showImportTour | Boolean | 是否展示引导浮层 |
| dontRemindAgain | Boolean | 是否勾选"不再提示" |
| recommendationMap | Object | 按文件组成维护的推荐附件集合 |

### 交互说明

- 入口位置：附件格式说明正下方，独立一行，与卡片左边缘对齐，不缩进。
- 纸质扫描件模式下不展示入口。
- 无文件组成、投标/调价环节同样不展示入口，此时附件区保持原状，直接展示文件组成部分，不出现导入相关的按钮、完成提示与建议文案。
- 引导浮层指向一键导入按钮，点击浮层按钮直接进入导入弹窗。
- 导入步骤：步骤一说明推荐逻辑 → 加载态 → 步骤二预览推荐结果 → 确认带入。
- 去重规则：按文件 ID 去重，推荐附件追加在已有附件之后，不覆盖已有附件。
- 完成反馈：入口隐藏，展示绿色完成提示（约 3 秒）。

### 异常处理

- 推荐为空：预览区展示"暂无数据，可点击手动添加"，仍可手动补充。
- 重复导入：入口已隐藏，无法再次触发。
- 推荐失败/超时：结束加载态并提示，允许重新发起。

### 性能要求

- 推荐结果返回 ≤ 2s，超时需给出进度或失败反馈
- 确认带入后页面更新 ≤ 300ms

## 4.3.3 导入后文件组成部分展示与核对建议

### 页面概述

导入确认后，以"文件组成部分"结构展示各分类及其附件，并在列表下方给出核对建议，引导用户先检查再提交。

### 页面布局

```
|  +----------------------------------------------------------+ |
|  | * 法人身份证                                              | |
|  |   [IMG] 58052193124060022401088623860.jpg  1.2MB      ✕  | |
|  |----------------------------------------------------------| |
|  | 工商企业信用等级   模板下载                               | |
|  |   [PDF] 工商登记信息证明.pdf  920KB                   ✕  | |
|  |----------------------------------------------------------| |
|  | 其他文件   推荐附件（样式与普通附件一致，无 AI 标识）      | |
|  |   [+ 添加附件]                                            | |
|  +----------------------------------------------------------+ |
|  建议：请先检测报名文件完善性，再提交报名                     |
```

### 功能点说明

| 功能点 | 功能描述 | 操作方式 | 数据来源 |
|--------|----------|----------|----------|
| 结果展示时机 | 完成导入或存在附件时展示文件组成列表 | 自动 | 本地状态 |
| 分类展示 | 按文件组成展示名称、必填标识、模板下载 | - | 数据配置 |
| 附件行 | 单行展示文件类型、名称、编辑与删除入口，卡片宽度随文件名长度自适应，不展示文件大小 | 点击删除 | 当前附件 |
| 推荐附件 | 与普通附件一致，不展示 AI 标识与推荐依据 | - | 推荐结果 |
| 添加附件 | 分类内追加附件 | 点击添加 | 文件助手 |
| 建议文案 | 导入后在列表下方展示橙色核对建议 | 自动展示 | 本地状态 |

### 数据字段定义

| 字段名称 | 字段类型 | 显示说明 |
|----------|----------|----------|
| category.title | String | 文件组成名称 |
| category.required | Boolean | 必填时标题前展示红色 * |
| category.hasTemplate | Boolean | 是否展示"模板下载" |
| file.name | String | 附件名称，单行省略 |
| file.size | String | 附件大小，列表内不展示（仅数据保留） |
| file.signingStatus | Enum | 签章状态标签（签署中/签章完成），导入文件初始为空 |
| adviceText | String | 建议：请先检测报名文件完善性，再提交报名 |

### 交互说明

- 展示顺序：文件组成按配置顺序排列，附件按已上传 → 推荐追加的顺序展示。
- 未导入且无附件时不展示列表，避免空白占位。
- 建议文案位置：文件组成列表下方，导入完成前不展示。
- 推荐附件与普通附件交互一致：可删除、可继续追加，不再额外标注来源。
- 删除附件后列表实时更新；最后一类附件清空后列表仍保留分类与添加入口。

### 异常处理

- 分类无附件：仅展示分类标题与"添加附件"按钮。
- 文件名超长：单行截断，不撑高行高。
- 导入后用户删除全部附件：列表保留结构，建议文案仍展示，提示可重新添加。

### 性能要求

- 列表渲染 ≤ 500ms
- 删除/追加附件反馈 ≤ 300ms

| 3. 触发导入 | 点击一键导入 → 开始一键导入 | 引导浮层 / 导入弹窗 | 首次进入有引导 |
| 4. 确认结果 | 在预览中确认带入页面 | 入口隐藏，展示文件组成部分 | 结果结构化可见 |
| 5. 核对附件 | 查看各文件组成 | 列表下方展示建议文案 | 新增核对引导 |
| 6. 后续提交 | 补充或直接提交 | 保持原有提交逻辑 | 不变 |

# 6. 测试标准

## 6.1 功能测试标准

| 用例 | 前置条件 | 操作 | 预期结果 |
|------|----------|------|----------|
| 卡片展示 | 展开报名附件 | 观察盖章方式区 | 两卡平分整行，无字段名，电子签章带推荐角标 |
| 卡片选中态 | 展开报名附件 | 交替点击两张卡片 | 选中卡橙色描边 + 浅橙底，说明文案变绿 |
| 卡片对齐 | 展开报名附件 | 观察下方说明与入口 | 说明、一键导入、列表与卡片左边缘对齐 |
| 入口位置 | 选择电子签章 | 观察入口 | 入口位于格式说明正下方、独立成行 |
| 入口隐藏 | 完成一次一键导入 | 观察入口 | 一键导入按钮不再展示 |
| 纸质模式 | 选择纸质扫描件 | 观察入口 | 不展示一键导入 |
| 无文件组成 | 附件区无任何文件组成 | 观察附件区 | 不展示一键导入，也不出现空的文件组成容器 |

## 6.2 性能测试标准

- 卡片切换与入口显隐 ≤ 200ms
- 一键导入推荐返回 ≤ 2s
- 文件组成列表渲染 ≤ 500ms

## 6.3 用户体验测试标准

- 无需精确点中单选点，整卡可点
- 电子签章优势文案在卡片内一眼可读
- 导入后用户能明确看到"导入了哪些文件、属于哪类附件"

# 7. 非功能性需求

## 7.1 性能需求

- 报名附件区展开/收起 ≤ 300ms
- 推荐接口超时 ≤ 10s，超时展示失败提示

## 7.2 可用性需求

- 模式切换、导入操作失败时保留已有输入与附件
- 引导浮层可勾选"不再提示"，避免重复打扰

## 7.3 安全需求

- 文件助手仅可访问当前账号权限范围内的文件
- 上传附件需校验格式、大小

## 7.4 数据统计需求

- 电子签章选择率（迭代前后对比）
- 一键导入曝光、点击、确认带入与放弃事件
- 导入后到提交的转化与附件补传情况

# 8. 迭代规划

| 阶段 | 范围 |
|------|------|
| 本期（原型） | 盖章方式卡片化、一键导入入口下移与导入后隐藏、文件组成部分展示、建议文案、推荐附件样式简化 |
| 后续 | 对接真实推荐接口与电子签服务回调、签章失败重试、附件完善性自动检测 |
| 保持现状 | 联系方式、底部提交按钮、提交失败弹窗与成功提示逻辑不变 |
