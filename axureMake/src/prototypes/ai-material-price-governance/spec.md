# AI 物料标准化与价格治理平台原型规格

## 1. 原型目标
基于价格库 PRD 与会议纪要，完整演示“数据接入清洗 → 分派专家任务 → 专家组装标准物料 → 运营入库审核（确认是否入标准库）→ 标准物料库沉淀 → 采购清单与物料映射应用 → 价格分析 / 智能询价 → 未匹配项回流治理”的业务闭环。

## 2. 页面信息架构
原型采用单入口、多业务视图结构。“价格库”为左侧一级菜单，默认展开 10 个二级菜单（另有 3 个「从列表进入」的隐藏二级页不计入菜单），**菜单顺序即演示动线**：数据接进来 → 派给专家 → 专家组装 → 运营审核 → 沉淀标准库 → 业务用起来 → 最后看总览。点击二级菜单切换对应业务页面：
1. **数据接入清洗**（`import`，菜单原名「数据源接入」）：真实上传 Excel / CSV / PDF，浏览器端解析表格或文本，调用大模型完成字段映射与规格型号的原子属性拆解，确认后生成治理任务。
2. **专家任务**（`tasks`，菜单原名「任务追踪」）：按品类、工程局把治理任务分派给业务专家，展示进度、待审核 / 逾期状态与「去处理 / 继续治理 / 去审核」入口。
3. **专家治理工作台**（`governance`，菜单原名「AI治理工作台」）：通栏属性列表 + 下方清单行预览 + 相似标准推荐列表 + 吸底操作条，专家确认属性名、属性同义词与商品历史叫法后「保存并提交审核」，不直接写标准库。
4. **运营入库审核**（`review`，菜单原名「入库审核」）：审核业务专家组装完成的商品（商品名称 / 规格型号 / 属性同义词 / 商品历史叫法）。**先区分提交方式**：新增建档 = 通过后新开一条标准物料；修改已有 = 通过后把变更合并进目标标准物料（编码 / 名称 / 价格记录不变）。驳回 = 退回专家治理工作台修改后重新提交。
5. **审核组装结果**（`review-detail`，不从菜单进入）：运营入库审核列表点「审核 / 详情」**跳转到本页**（不是右侧抽屉），逐条核对组装结果并给出通过 / 驳回结论。
6. **标准物料库**（`standards`）：支持搜索、品类筛选、规格型号查看和标准物料详情追溯，每行提供「编辑」进入编辑页。
7. **编辑标准物料**（`standards-edit`，不从菜单进入）：逐条维护标准名称、编码、品类路径、规格型号与历史叫法，保存后写回本地快照。**单栏整幅铺开，不再有「本库物料」侧栏**（业务方 2026-10-25 明确要求移除）。
8. **编制采购清单**（`purchase-list`）：还原询比采购清单编制场景，包含单据头部、响应倒计时与采购信息、采购阶段进度、清单模板与清单名称、商品明细表格（含**参考价列**，可穿透到价格分析）、清单附件、私有库建议栏和分供商报价说明。
9. **物料映射**（`material-mapping`）：历史招标清单与标准物料库的对账入口——上面是历史招标列表（含映射进度与已归集的可复用历史价），点「映射」进入该招标的清单映射工作台；一条标准物料可对应多条历史非标写法（一对多），映射后按标准属性口径补规格型号，历史成交价才真正可用（详见第 13 章）。
10. **清单映射**（`mapping-detail`，不从菜单进入）：单个招标的清单逐条映射工作台，左侧清单表 + 右侧 sticky 面板，面板里做「系统推荐候选 → 选定标准物料 → 补充 / 修改规格型号 → 确认」。
11. **价格分析**（`analysis`）：一件商品的招采历史与签约情况看板——4 个关键指标 + 合同金额走势 + 区域分布 + 工程局占比 + 年度结构 + 合同明细，**参考价就来自这里**，采购清单参考价列「查看详情」跳入本页。
12. **智能询价**（`inquiry`）：贴清单或上传供应商报价表，AI 匹配标准物料后，用历史成交价画像（参考价 + P25~P75 区间）判断这次报价贵不贵；每行可穿透到价格分析，未匹配项回流治理。
13. **治理总览**（`overview`，菜单最后一项）：**闭环看板**——五个可追溯的 KPI + 与菜单同序的七步闭环（每步带真实指标与状态）+「下一步建议」与四个卡点 + 治理任务与审计动态 + 品类 / 价格 / 产出三块结构图；首次打开不落这一页，演示从「数据接入清洗」开始，总览作为整条链路跑完后的收尾（详见第 14 章）。

> 菜单顺序验证：`temp/menu-check.mjs` 15 项 ALL PASS（10 项菜单文案与顺序、首屏落 `import`、逐项点菜单核对页头标题、总览闭环七步与新顺序一致且每步都有指标）。侧边栏高度不够时本原型会把「价格库」一组提到「首页」之后，详见 `index.tsx` 注释。

## 3. 闭环交互
- 编制采购清单支持新增商品、勾选删除、编辑清单名称、填写私有库建议与分供商报价说明，选中条数实时统计；保存、下一步、导出清单等操作给出反馈。
- **参考价贯穿清单与价格分析**：清单每行的「参考价」与该行含税单价做比对并标出偏离，点「查看详情」跳到价格分析页看这件商品的历史招采与签约明细；两处价格同源于 `refPriceOf`，不会出现两个数。
- 总览的七步闭环节点、五个 KPI、四个卡点都可点击直达对应页面；「下一步建议」按「待审核 > 驳回待改 > 还没接入 > 历史清单未映射 > 都没事去询价」的优先级算出当前最该做的一件事。
- 数据接入清洗为真实文件链路，三步：上传数据 → 字段映射 / 文本确认 → AI 原子拆解；确认导入后待治理量按实际条数增加，并在「专家任务」生成治理任务，由专家在「专家治理工作台」确认。
- 治理工作台可勾选原子属性、实时生成标准名称；发现标准库已有同一件商品时，可在相似标准里「关联此标准，按修改提交」，此时提交的是相对该标准物料的**变更明细**（改值 / 新增属性 / 新增历史叫法）。点「保存并提交审核」生成提交单：本任务状态转「待审核」并跳到入库审核页；审核通过后，新增建档使标准物料数 +1，修改已有则合并进原标准（数量不变）；驳回则带着审核意见退回。
- 运营入库审核列表点「审核 / 详情」**跳转到独立页面**「审核组装结果」（`review-detail`），页面内可「下一条待审核」继续审、可「返回运营入库审核」；通过需二次确认——新增建档写库（「通过并入库」）、修改已有合并进目标标准（「通过并合并」），驳回必须填写意见。全部物料通过后任务状态转「已完成」。
- **智能询价与价格分析双向联动**：询价结果每行的「价格分析」把该商品带进价格分析页（`openPriceAnalysis(subject, 'inquiry')`），价格分析页的返回按钮随之变成「返回智能询价」；询价结果落本机快照，来回跳转与刷新都不丢。判定不用拍脑袋的价格线，而是 P25~P75 的成交区间（详见第 12 章）。
- 专家任务中的「去处理 / 继续治理」进入治理工作台时，带入该任务自己的物料数据（而非全局"最后一次导入"）；导入任务、进度、标准物料与当前页面均持久化在浏览器本机，刷新后不丢失，详见第 7 章。
- **物料映射把历史价格接进标准口径**：招标列表点「映射」→ 清单映射工作台，进项目即按历史叫法与规格属性自动预映射，专家只做复核与改判 → 提交后该招标的确认条数与金额进入「可复用历史成交价」指标，映射关系落本机快照（刷新仍停在原招标、结果不丢）。一条标准物料可挂多条历史写法（一对多），已挂过的写法下次自动命中，不再重复建档。

## 4. 设计规范
- 顶部与左侧菜单统一复用 `CentralizedProcurementLayout`；“价格库”作为一级菜单，业务页面作为其二级菜单展示并标记当前选中项。
- 采购阶段进度统一复用 `src/components/step-bar` 的 `StepBar` 组件（主流程箭头条 + 子流程节点），页面内仅通过 `.pl-stepbar` 微调配色与间距。
- 除“编制采购清单”外，其余价格库业务页面统一使用“12px 灰色面包屑（价格库 › 当前页面）+ 主蓝色类型标签 + 14px 单据式标题栏 + 右侧页面操作”的页头；页头与下方内容保持 14px 间隔，窄屏时标题栏自动换行。
- 单据标题栏与基本信息栏横向贴合内容区边缘且上下无间隔，标题操作栏独立于基本信息容器并在内容滚动时吸顶；采购阶段条作为独立卡片与基本信息保持 12px 间隔；基本信息采用固定标签列右对齐、内容列左对齐的四列网格。
- 当前主流程节点的蓝色长方形与蓝色三角箭头无接缝；已完成子流程节点使用蓝底白色对钩。
- 卡片模块标题的蓝色色块紧贴卡片左侧边缘，标题文字随色块一起靠近边缘，右侧操作与折叠按钮保持内边距。
- 主背景使用 `#f5f5f5`，主强调色为 `#0081cc`，正文使用黑灰色阶。
- 采用克制的 12–20px 字号、2–6px 圆角、轻量蓝色阴影；不使用深色大面积背景。
- 涨价/高价提示使用红色系，符合国内价格业务阅读习惯。

## 5. 核心业务规则
- 原始治理范围聚焦近五年高频物料，优先钢筋、水泥、管材。
- 品牌与价格来源优先级：合同文本 > 招标清单；不纳入结算单。
- 低置信度、异常价格必须经人工确认。
- 跨工程局价格仅展示脱敏后的参考区间和来源摘要，不暴露合同条款。
- 标准物料和价格均保留原始来源、AI 结果、专家操作等审计链路。
- 治理进度以「已确认入库的物料」为口径，跳过、废弃不计入完成；一个导入批次对应一条治理任务，任务与批次数据强绑定。

## 6. 数据接入清洗（真实 AI 能力）

### 6.1 支持的文件
| 类型 | 解析方式 | 后续流程 |
|------|----------|----------|
| xlsx / xls / csv | SheetJS 读取，按关键词评分定位表头行（避免把「项目名称」标题行当表头），支持两行表头合并（单价 / 不含税单价 → 单价-不含税单价），按内容裁掉尾部空列，最多取 200 行预览 | 字段映射 → AI 拆解 |
| pdf | pdf.js 逐页提取文本块，按 y 坐标聚合成行、合并被断开的中文，剔除表头及之前的标题/编号等版式文本 | 文本确认 → AI 拆解 |

限制：单文件 ≤ 30MB；单次最多拆解前 30 条物料（`MAX_ITEMS`），以保证演示耗时可控；扫描件 PDF 无文本层时不再直接报错，而是进入「文本确认」并给出 OCR / 粘贴引导。

### 6.2 字段映射
- 业务字段：物料名称（必填）、规格型号、计量单位、数量、含税单价。
- 默认本地关键词映射（`guessMapping`）即时给出结果；「AI 智能识别」按钮会把表头与前三行样例交给模型判定列归属，失败时不阻塞手动选择。
- 无法判断的字段统一映射为「忽略此字段」，不阻塞拆解流程。
- 报价表常把规格写在「项目特征」列（而非「规格型号」），已纳入规格型号的别名；列名含否定词（不含税 / 未含税）的不参与该字段匹配。

### 6.3 AI 原子化拆解
- 提示词要求：每条输出 3–8 个原子属性，首个属性必须是「品类」；value 归一化、不含品牌产地价格数量；置信度 0–100，推断项 ≤75。
- 归一化硬约束：区间统一写 `Φ8~Φ10mm`；「以内」转 `≤`、「及以上」转 `≥`；「综合」牌号合写为 `HRB400/HRB400E`；同品类输出同一组属性（钢筋固定 品类/牌号/直径/表面形状/用途），原文无牌号时省略牌号并压低整条置信度。
- 分批串行调用（`BATCH_SIZE = 8`），逐批回传结果；界面展示真实批次进度、模型思考字数与流式输出片段（可中断）。
- 失败批次标记为「失败」并保留原因，支持只重试失败项；单条结果可展开编辑属性名 / 属性值 / 置信度，也可删除或补充属性。
- 标准物料名由勾选原子属性按顺序拼接生成，与治理工作台保持一致。
- 非物料行（合计 / 质量标准 / 付款方式 / 发票税金 / 供货时间 / 其它事项 / 供应商 / 联系人 / 签章 / 报价时间 等）在生成待拆解明细时自动剔除，界面提示「已跳过 N 行」，避免条款被当作物料入库。
- 结果表支持逐行删除：行尾「操作」列的操作按钮直接移除该行，统计（成功数、平均置信度、可导入数）实时重算；被删行进入暂存区，表底显示「已删除 N 条 · 撤销」可一键恢复并保持原序号。`running` 期间删除不影响在途批次（结果按 key 回填，已删除行不会被写回）。失败批次另有「删除失败项」批量清理。

### 6.4 模型接入方式
- 配置项：API 地址、模型名称、API Key，默认值来自 `doc/apikey.md`，保存在浏览器 localStorage，可在页面「模型配置」中覆盖或恢复默认。
- 浏览器直连第三方网关会被 CORS 拦截，因此请求统一走本地开发服务器代理 `/llm-proxy/chat/completions`（`vite-plugins/llmProxyPlugin.ts`），由代理按 `x-llm-base` 头转发并以 SSE 透传；代理不可用时自动回退直连并给出跨域提示。
- 该能力仅用于原型演示：Key 在前端明文可见，生产环境需改为后端代理并做密钥托管与用量管控。

### 6.5 真实清单实测（2026-10）

| 样例 | 类型 | 解析结果 | 拆解结果 |
|------|------|----------|----------|
| 贵阳首钢保障房-铝合金踢脚线采购清单 | xlsx（两行表头 + 合并单元格 + 大量空白列） | 表头正确合并为 10 列，识别 11 行，剔除 10 行条款/签章 | 1 条物料，置信度 92%；品类踢脚线 / 材质铝合金 / 高度 50mm / 厚度 0.8mm / 形态成品 / 用途装饰面层 |
| 郑州经开-物资总需求计划（钢材 13 行） | pdf（扫描件，无文字层） | 无文字层，走文本确认 + 粘贴 | 13 条全部成功，平均置信度 86%；区间与牌号写法完全归一化 |
| 附件一：报价表（钢筋 3 行） | xls（含标题行、工程名称行、合计行、盖章行，规格写在「项目特征」列） | 表头定位到第 3 行，识别 5 行，剔除 2 行（含税合计 / 响应单位盖章） | 3 条全部成功，平均置信度 85–87%；`高线HPB300`→钢筋/HPB300/Φ6~Φ12mm/光圆；第 3 行「螺纹钢HRB400E、HRB500E、圆钢、高强螺纹钢」为一价多牌号合并行，归一为 `牌号 HRB400E/HRB500E`、`表面形状 带肋/光圆`，置信度降到 65–82% 提示人工复核 |

已知限制：扫描件仍依赖人工粘贴或外部 OCR；同一物料在不同清单中的叫法差异（如「HRB400以内」）已按规则归一，但极简描述（仅「钢筋 Φ10以内」）只能靠行业常识补全，置信度会落到 66% 左右并进入人工复核。

## 7. 前端数据持久化与任务闭环

原型没有后端，但「导入 → 建任务 → 治理 → 回看进度」必须在刷新、切换页面后仍成立，因此把可变状态整体快照到浏览器 `localStorage`。

### 7.1 存储内容

| key | 内容 | 说明 |
|-----|------|------|
| `ampg:demo:v1` | 当前页面、待治理/标准物料/有效价格计数、标准物料库、治理任务（含导入批次物料）、价格决策、当前治理任务、每条任务的物料游标、属性手工改动（`atomOverride`）、商品名称同义词（`materialSynonym`）、**入库提交单（`submissions`）**、**物料→标准物料的关联（`materialLink`）**、**历史清单项的物料映射（`mapping`）与当前招标（`activeBidKey`）** | 单一快照，带 `version`；版本不匹配或结构非法时整体丢弃并回落到初始演示数据。旧快照缺少 `submissions` 时按 key 补回演示提交单、缺少 `materialLink` 时由「修改类」提交单反推、缺少 `mapping` 时回落到 `initialMappings()` 种子、缺少 `activeBidKey` 时置 `null`，都不让整份快照失效 |
| `ampg:import-draft:v1` | 最近一次未导入的拆解结果（含原子属性、置信度、来源文件名） | 刷新后可「恢复 / 丢弃」，避免重新付费调用模型 |
| `ampg:purchase-draft:v1` | **编制采购清单的草稿**：清单名称、全部清单行（含参考价快照）、清单附件及其解析结果（`rows`）、私有库建议、分供商报价说明 | 独立 key，不塞进主快照：附件解析结果体积大，混进去会拖慢其它页面每次读写。清单页挂载时读、变更后 300ms 防抖写、**卸载时同步 flush**（点参考价跳价格分析正是先卸载）；恢复时把未解析完的附件标成「解析中断」，不让进度条永远卡住。`clearDemoState()` 一并清理 |
| `ampg:ai-config:v1` | 模型地址、模型名称、API Key | 沿用原有实现 |

- 写入时机：任一状态变化后同步写入（单批演示数据约 3–6 KB）；写入失败（隐私模式 / 配额满）静默降级为纯内存，不阻断操作。
- 专家任务页展示「本机已保存 N 项 · X KB · HH:mm:ss」，并提供「重置演示数据」清空全部本机数据，恢复初始 4 个任务与 4 条标准物料。

### 7.2 数据链路：导入批次与任务一一对应

- 「确认并导入治理」不再只是写内存数组，而是创建一条 `GovernanceTask`，并携带 `source`：
  - `fileName / sheetName`：来源清单与工作表，用于任务命名与治理页顶部「导入批次」条；
  - `materials`：本次导入并完成拆解的物料（原子属性、置信度、单位、原始描述）；
  - `confirmedKeys`：**审核通过、已入库**的物料 key，是进度与「下一条」定位的依据；已提交待审核的物料另由 `submissions` 记录。
- 任务命名取文件名去扩展名 + `· 专家治理`；品类为单一品类时直接使用，多品类显示「多品类（N 类）」；截止日期默认导入后 7 天，业务专家默认张工。
- **导入成功后落点是专家任务**：只建任务并定位到该任务，不直接把用户拽进工作台，让「任务已生成」这件事先被看见；用户从任务行点「继续治理」才进入工作台。
- 专家任务「继续治理」调用 `openTask(taskKey)`：把该任务设为当前任务，游标定位到**第一条未确认物料**，再跳转治理工作台；因此连续导入多批文件后，各任务互不串数据。
- 治理工作台只读当前任务的 `source.materials`；没有当前任务时才回落到内置钢筋演示物料。

### 7.3 交互规则

- 专家在治理工作台点「保存并提交审核」，生成一条 `MaterialSubmission`（待审核）：商品名称、规格型号、属性同义词、商品历史叫法全部快照进去，同时记下**提交方式**（新增建档 / 修改已有物料）与变更明细；任务状态按已提交比例转为「待审核」，页面跳到入库审核。
- **审核通过**按提交方式分两条路：新增建档 → 写入标准物料库（编码 `STD-AI-xxxxxx`）、标准物料数 +1；修改已有 → 把属性值 / 属性同义词 / 商品历史叫法**合并进目标标准物料**，编码、名称、品类路径与价格记录保持不变，标准物料数不变。两种情况都把物料加入 `confirmedKeys`、待治理量 -1；**驳回**只改提交单状态并带回审核意见，不写标准库。
- 任务状态：`进行中`（还有物料没提交）→ `待审核`（本任务物料已全部提交，等审核）→ `已完成`（全部审核通过）；`completed` 只统计已通过入库的条数。
- 已入库 / 已提交待审核的物料不能重复提交（按钮置灰），驳回的物料可以「修改后重新提交」，提交单会累计 `attempt`。
- 当前任务全部提交后，治理工作台展示完成态（等审核 / 全部入库两种文案），提供「去入库审核 / 查看标准物料库 / 专家任务」出口，不再回落到演示数据。
- 专家任务中导入任务带「导入」标签、来源文件与条数副行，操作按钮为「继续治理」；待审核任务显示「去审核」，已完成任务显示「查看成果」；任务量下方补一行「待审核 N 条」。
- 刷新页面后停留在原页面；若原页面是治理工作台，仍显示同一任务与同一条物料位置。

### 7.4 已知边界

- 数据只存在当前浏览器、当前域名下，换浏览器 / 清缓存即丢失；原型不提供账号级同步。
- `localStorage` 容量约 5MB，按单批 30 条物料估算可容纳上百个批次，超出后写入失败并静默降级（页面仍可用，但刷新后新数据丢失）。
- 导入页的原始表格对象（表头与预览行）不持久化，只保留拆解结果；「恢复草稿」直接进入结果阶段，如需改字段映射需重新上传。

## 8. 治理工作台：商品行表格化与属性列表

页面自上而下：待治理商品表格 → 属性抽取原子列表（通栏）→ 预览（入库后在商品清单里的样子）→ 相似标准推荐（列表）→ 吸底操作条。

### 8.1 待治理商品表格

工作台顶部新增「待治理商品」表，把「本批次有哪些商品、做到哪一步」一次性摆出来，替代原来只能靠「当前 x/y」盲猜的方式。

| 列 | 内容 |
|----|------|
| # | 批次内序号 |
| 商品原始描述 | 来源文本，溢出省略 + Tooltip；当前处理中的行额外挂「当前」标签 |
| 品类 / 属性 | 品类、属性条数（含「N 空值」提示） |
| 同义词 | 该商品已登记的同义词条数（属性级 + 商品名称级合计），没有则显示「—」 |
| 单位 / 置信度 | 计量单位；高（≥90%）/ 中（75–89%）/ 低（<75%）三档配色 |
| 状态 | 已入库 / 处理中 / 待处理 |
| 操作 | 待处理显示「处理」，已入库显示「查看」（固定右侧） |

- 交互：**整行可点**，点击即切换当前物料（写入该任务游标），下方属性列表、组装预览同步刷新；当前行以浅蓝底 + 左侧主色竖条高亮。
- 顶部提供「全部 / 待处理 / 已入库」分段筛选（带条数）与描述/品类关键词搜索；超过 6 行时表格内部纵向滚动，避免把下方工作区挤出首屏。
- 已入库商品仍可点开复核，再次「确认入库」不会重复计数（`confirmedKeys` 去重）。

### 8.2 属性列表（列表形态）

属性区从原来的「一条属性一张小卡片」改为**表格式列表**，一行一条原子属性，列为：

`勾选 | 属性名 | 属性值 | 同义词 / 历史叫法 | 置信度 | 操作`

- 表头吸顶、行间细分隔线、悬停整行浅蓝高亮；未勾选的行整体降透明度（`is-off`），一眼看出哪些属性会参与组装。
- 每行高度约 42px，属性多时信息密度显著提高；窄屏（<820px）隐藏置信度列，避免挤压同义词区。
- 「品类」行操作列显示小锁，不可删除（主键）；其余行悬停出现删除按钮。

### 8.3 属性级同义词 / 历史叫法

解决的问题：历史文件对同一个规格属性的叫法五花八门（「直径 / 规格 / Φ径 / 断面直径」），如果不登记，系统会把它们当成不同属性。

- 每条属性右侧有同义词区：已登记的以 Tag 展示（可单条关闭），尾部固定「+ 添加」。
- 点「+ 添加」在行内出现输入框（不弹窗、不跳转），回车或失焦提交；空值与重复值会被拦截。输入框的 placeholder 与悬停提示会带出该属性名的常见历史写法（来自 `data.ts` 的 `defaultAtomSynonyms`）。
- 数据落点：属性同义词随属性一起存进快照 `atomOverride[物料key]`（`Atom.synonyms: string[]`），刷新后仍在；「数据接入清洗」导入时按 `defaultAtomSynonyms` 自动预填，专家只需增删。
- **商品名称同义词**同样支持多条：右栏「商品名称同义词 / 历史叫法」用 Tag 列表 + 输入框维护（回车添加、Tag 可关闭、重复拦截），底部提供「用原始描述作为历史叫法」快捷补充；写在快照新增的 `materialSynonym[物料key]`，与属性改动互不覆盖。
- 确认入库时一起落库：
  - 商品名称：`synonyms = 去重(专家登记的多条 + 原始描述)`；
  - 属性级：`attributeSynonyms: { 属性名: [历史叫法...] }`，只登记勾选参与组装的属性、且只写非空集合。
- 「质量提示」会显示「N 条属性已登记历史叫法，商品名称另有 M 条」，没有登记时用橙色提示「历史文件的异名写法会匹配不上」。

### 8.4 属性名 / 属性值的内联编辑

本页的核心任务由业务专家**核对 AI 拆出的属性名是否准确**，因此属性值一律非必填：可以只补充属性名，也可以把已有属性值清空。

- **补充属性**：点击打开弹窗，「属性名称」必填、「属性值」选填（可留空，后续再补）、「同义词 / 历史叫法」选填（逗号分隔，也支持空格/分号）；提供 8 个常用属性名（规格型号 / 材质 / 执行标准 / 品牌 / 颜色 / 厚度 / 长度 / 表面处理）标签，点一下即填入名称。
- 提交后新原子追加到当前物料属性列表、**自动勾选**并进入组装预览，置信度记为 100%、行内标注「手工」（区别于 AI 语义抽取）；值为空时显示灰色斜体「（空）」。
- **点击属性名**变输入框可改名（回车/失焦保存），改名不能为空；「品类」是标准物料主键，禁止改名与删除，点击给出提示。
- **点击属性值**就地变输入框，回车或失焦保存；**允许清空**。
- 组装预览：名称由已勾选且非空的属性值拼接，全为空时显示「待补充属性值」；入库后空值属性在标准库里记为「待补充」（品类为空时回落到物料自身品类）。
- 手工改动按物料 key 整组写入快照，刷新后仍在；未改动的物料继续沿用原 AI 结果，不额外占体积。
- 页脚操作条随页面滚动**吸底常驻**（`position: sticky`），含「跳过此条 / 标记废弃 / 拆分处理 / 确认入库」，左侧说明同义词会随入库一起写进标准物料。

### 8.5 预览（入库后在商品清单里的样子）

原来右栏是「组装预览」卡片堆（大号名称 + 属性两列小卡片），既占宽度又不直观。现在改成**清单里的一行**：属性列表通栏，预览放在它下面，一眼就能看出确认入库后这条物料在「编制采购清单」里的样子。

- 标题就叫「预览」，右侧一行小字说明「入库后在商品清单里的样子 · 随勾选的属性实时生成 · 数量、单价、合价为示例值」。
- 形态：一条灰色表头 + 一行数据，列与采购清单前段保持一致：序号 / 商品名称 / 规格型号 / 单位 / 数量 / 含税单价 / 合价 / 税率 / 报价依据（「标准物料库」标签）。
- 取值：
  - 商品名称 = 已勾选且非空的属性值按空格拼接（与入库后的标准名称同源）；
  - **规格型号 = 该单元格内逐行竖排「属性名：值」**（如 `牌号：HRB400E` / `直径：Φ25mm` / `外形：热轧带肋` / `特性：抗震`）。这是同一个商品行里同一格的多行，不是多条商品行；「品类」不重复展示；
  - 单位 = 物料自身单位；报价依据固定为「标准物料库」；
  - 数量 100、单价按品类取示例值（钢筋 3860 / 水泥 468 / 管材 62 / 电缆 28 / 灯具 118 …）、合价 = 数量 × 单价、税率 13%，均为示例，表头右侧明确标注。
- 实时联动：勾选/取消勾选属性、改名、改值都会立刻反映到这一行；取消掉某条属性，名称与规格同步变少一行。
- 「商品名称历史叫法」与「质量提示」从右栏移到预览下方，按「标签 + 内容」两行铺开，不再占独立卡片。
- 未展示的列（品牌名、不含税单价 / 合价、税额）由清单页按 13% 税率反算，预览下方一句话说明，避免误以为漏字段。
- 窄屏（≤1180px）先让出「报价依据」列，≤820px 再让出「合价 / 税率」，保证名称与规格不被压扁。

### 8.6 相似标准推荐（列表 + 展开明细）

原来三张卡片点了只弹一句提示，看不到依据。现在改成**列表**，点任意一行就地展开明细：

| 列 | 内容 |
|----|------|
| 标准物料 | 标准名称 + 编码（等宽蓝字）/ 品类路径；命中商品历史叫法时挂「历史叫法命中：xxx」绿标 |
| 属性一致 | `m/t` 项，m = 属性名与取值都相同的条数，t = 当前勾选参与对比的属性条数 |
| 价格数据 | 该标准关联价格条数 + 均价（来自 `initialPrices`） |
| 匹配度 | 属性命中率（完全一致 1 分、同名不同值 0.6 分，按参与对比的属性数折算），右对齐 |

- 候选与排序都是真实的：取 `context.standards`，用「当前属性名 + 已登记同义词 + `defaultAtomSynonyms`」归一后与标准侧属性名匹配，打分 ≥40 才进列表，按匹配度降序取前 4；没有候选时提示「当前属性与标准库没有重叠，入库后会作为新标准建档」。
- 点行展开（再次点击 / 切换其它行收起），明细三块：
  - **属性对比**：`属性 | 当前商品 | 该标准物料`，按 `is-same / is-diff / is-missing / is-extra` 上底色，差异值橙色加粗；
  - **价格与历史叫法**：价格记录数、均价、价格区间、最近成交（日期），以及该标准已登记的整条物料历史叫法 Tag；
  - **差异与建议**：用一句话拼出「需确认的取值差异 / 本商品有而标准没登记的属性 / 该标准多出的属性」，全一致时提示可直接关联避免重复建档。
- 明细内三个操作：「查看标准物料」跳转标准物料编辑页；「按该标准对齐属性」先弹确认框，确认后用 `applyAtoms` **一次性**把该标准的属性值写回当前物料（同名属性改值、缺失属性补进属性列表，属性名与已登记同义词不动），并自动全选、预览同步刷新。批量写回故意不走多次 `updateAtom`——连续调用会基于同一份渲染快照互相覆盖。**「关联此标准，按修改提交」**见 §8.8。
- 窄屏（≤1180px）隐藏「价格数据」列，≤820px 再隐藏「属性一致」。

### 8.7 吸底操作条

「保存草稿 / 标记废弃 / 保存并提交审核」与说明文案组成一条吸底栏，`position: sticky; bottom: -16px`：

- 文案两行：第一行说明本次提交去向——未关联标准时是「提交后进入入库审核…审核通过才写入标准物料库」，已关联时变成「本次是给 `STD-xxx` 打补丁，审核通过后合并进原物料，不会重复建档」；第二行回显当前商品状态——未提交显示草稿保存时间（已关联时改为「修改 STD-xxx · 变更摘要」），待审核显示提交时间与第几次提交，已入库显示标准编码与审核通过时间，已驳回显示审核意见。
- 去掉「跳过此条」「拆分处理」两个按钮：前者会让物料既不提交也不废弃、进度失真；后者属于任务拆分能力，不该混在单据确认动作里。
- 按钮文案随状态变化：未提交「保存并提交审核」、驳回后「修改后重新提交」、审核中「已提交审核」（置灰）、已入库「已通过入库」（置灰）。
- 点提交先弹确认框，逐条列出**提交方式**（新增建档 / 修改已有物料 + 目标编码）、商品名称、规格型号、历史叫法条数；修改模式追加「变更内容」（改值 N / 新增属性 N / 新增历史叫法 N）与前 6 条变更明细，超过 6 条提示「还有 N 项变更…」；结尾文案同步说明「合并进原标准」还是「按新增建档写入」。
- 布局容器 `.main-content` 有 16px 下内边距，sticky 按内容盒计算会留出 16px 灰边，因此用 `bottom: -16px` + `margin-bottom: -16px` 抵掉，滚动到底也不露灰边。
- 左右用 `margin: 0 -24px` 出血到内容区边缘，配 `box-shadow: 0 -4px 12px`，滚动时内容从它下方穿过。说明文案 `flex: 1 1 0; min-width: 0` 收缩、按钮组 `flex: 0 0 auto`，窄屏不会把主按钮挤出可视区。

### 8.8 提交审核与状态流转

**提交方式（新增建档 / 修改已有物料）**

专家组装时经常发现标准库里已经有同一件商品，只是属性值要改、属性要补、或历史叫法要加——这时不能重复建档，应当合并进原物料。因此提交前先确定「方式」：

- 关联入口在「相似标准推荐」每条展开明细的第三个按钮「关联此标准，按修改提交」；已关联时按钮变「已关联，点击取消」，卡片上标记「本次提交合并进这条」。
- 顶部出现一条常驻提示条：已关联 → 紫色「修改已有物料 + 标准名称 + 编码 + 变更摘要 + 「改为新增建档」」；未关联但存在 ≥85% 相似标准 → 黄色提示「与 STD-xxx 匹配度 N%，如果是同一件商品，关联后按修改提交，避免重复建档」+「关联此标准」，避免专家漏看而重复建档。
- 关联关系存 `materialLink[materialKey] = standardKey`（持久化）；只存关系不存快照，diff 在每次渲染/提交时按**最新**标准物料实时计算。
- 变更明细由 `similar.ts` 的 `diffStandardChanges` 统一算出（治理台与审核页共用一套算法）：
  - `value`：属性名命中（当前名 + 已登记同义词 + 内置常见写法）且值不同 → 记 `before / after`；提交值为空视为「本次不改这一项」，不会清空标准库；
  - `add-atom`：标准里没有这条属性 → 新增属性（值为空则不提交，避免落成「待补充」噪声）；
  - `atom-synonym`：属性上登记了标准侧还没有的叫法（标准侧已登记的 + 内置常见写法都算已有）；
  - `name-synonym`：商品历史叫法里标准侧没有的；
  - 「品类」不参与比较：它体现在标准物料的品类路径里，不是规格属性。
- 摘要文案 `describeChanges`：`改值 N 项 · 新增属性 N 项 · 新增历史叫法 N 条`，无差异时为「与目标标准一致，无属性变更」。

**状态与校验**

- 提交前校验：至少勾选一个属性、必须保留「品类」（标准物料主键）。
- 提交单 `MaterialSubmission` 字段：`taskKey / taskName / materialKey / sourceName / name / category / unit / bureau / atoms[{label,value,synonyms}] / synonyms / changeType('new'|'update') / targetStandardKey? / targetStandardCode? / targetStandardName? / changes[] / submitter / submittedAt / attempt / status / comment? / reviewer? / reviewedAt? / standardKey? / standardCode?`。
- 商品表格「审核状态」列四态：待提交 / 审核中 / 已入库 / 已驳回（悬停显示驳回原因）；待审核且为修改类时额外挂一个「改」小标，悬停说明「通过后合并进原物料，不会新建」；筛选分段为「全部 / 待提交 / 审核中 / 已入库」。
- 提交后游标自动推进到下一条未提交物料，回到工作台可以直接继续；全部提交后进入完成态。
- 内置演示预置三条提交单：一条新增建档待审核、**一条修改已有（`sub-seed-3`，关联 `STD-GJ-000129`）待审核**、一条新增建档已驳回；初始游标落在已驳回那条，一进工作台就是「驳回后改完重新提交」的场景。种子的变更明细由 `storage.createInitialState` 调 `diffStandardChanges` 现算，不手写，避免与算法跑偏。

### 8.9 入库审核：列表 + 独立详情页（2026-10-25 改版）

- **审核详情不再用右侧抽屉**，改为跳转独立页面 `review-detail`（页面标题「审核组装结果」，面包屑同步）。原因：组装结果要逐条核对属性名 / 属性值 / 每项属性的历史叫法，抽屉宽度不够、也容易被误关。
- **先看「提交方式」再看内容**：同一条审核队列里混着「新增建档」和「修改已有物料」，两者审核口径完全不同（前者要防重复建档，后者要确认改得对不对、合并进的是不是对的那条），所以提交方式单独成列：
  - 新增建档 → 蓝色 Tag + 「标准库无此物料」；
  - 修改已有 → 紫色 Tag + 目标标准编码（Tooltip 显示标准名称）+ 「N 项变更」。
- 列表页 `review`：4 个 KPI（待审核 / 已通过入库 / 已驳回 / 提交单总数，总数下拆「新增建档 N · 修改已有 N」）+ 两组筛选（状态四段 + 提交方式三段「全部方式 / 新增 / 修改」）+ 关键词搜索（可搜目标标准编码）；每行操作按钮按状态显示「审核」（待审核）或「详情」（已出结论），点击均跳详情页。
- 详情页结构（自上而下）：
  1. 商品名称（页面主标题）+ 7 项 meta（**提交方式** / 来源任务 / 原始描述 / 品类单位 / 提交人时间 / 提交批次 / 所属工程局），修改模式下提交方式用紫色强调「修改已有 · STD-xxx」；
  2. 状态 Alert（已驳回显示原因与审核人时间，已通过显示落库编码）；
  3. **「本次变更」区块（仅修改模式）**：一条一行，四列「变更类型 / 属性 / 标准库现值 / 本次提交」——改值行旧值带删除线、新值加粗，新增属性 / 属性同义词 / 商品叫法按类型染色；标题右侧给一句话摘要，底部说明「通过后只合并属性与历史叫法，编码 / 名称 / 品类路径 / 价格记录不变」；
  4. 「组装结果（审核对象）」三列表：属性名 / 属性值 / **该属性的历史叫法** + 商品名称历史叫法；修改模式下每行带变更标记（`改` / `新` / `同`），改值的值后补「（原 xxx）」；
  5. 相似标准卡：修改模式改成「本次提交是给该标准打补丁：通过后合并进它，**不会重复建档**」，并列出当前规格数与价格记录数；若另有 ≥85% 的其他标准，追加一行提醒「请确认目标标准选的是对的那条」。新增建档模式仍是原口径（≥85% 标红「疑似重复建档」）；
  6. 「审核意见」：待审核时可编辑（驳回必填），已出结论时只读；「用疑似重复作为意见」快捷入口只在新增建档模式出现；
  7. **吸底操作条**：左侧说明（修改模式改为「通过后把 N 项变更合并进 STD-xxx」）与队列剩余条数，右侧「回到该任务继续治理」/「查看已入库标准物料」（已通过时）/「驳回退回」/「通过并入库」或「**通过并合并**」（修改模式）。
- 页头右上提供「下一条待审核（N）」——队列里还有别的待审条目时才出现，审完无需回列表再点一次；「返回入库审核」始终在。
- 通过走 `Modal.confirm` 二次确认，确认框首行即写明提交方式；修改模式文案为「确认把变更合并进标准物料？…标准物料总数不变」，新增建档为「通过并写入标准物料库？…标准物料库 +1」。
- 目标标准物料若已不存在（数据被重置等），详情页给黄色 Alert 说明「通过后将按新增建档处理」，`reviewSubmission` 也按新建兜底。
- 驳回未填意见会被 `message.warning` 拦截且停留在当前页。

  - 标准物料编码（必填）、标准名称（必填）、品类路径；
  - **规格型号**：按行展示「序号 + 规格名称 + 规格值 + 删除」，可「添加一项」，也可用快速标签（牌号 / 规格型号 / 材质 / 执行标准 / 强度等级 / 功率 / 灯头口径 / 色温）追加；**规格值可留空**（保存后记为「待补充」），规格名称不能为空且不能重复；至少保留一条。
  - **每条规格型号自带「历史叫法」行**（见 9.5）：Tag 展示、单条可关闭，行内「+ 添加」出输入框，回车或失焦提交。
  - **商品名称的历史叫法**：与规格级分开维护的独立区块，Tag 展示 + 输入框追加，可以有多条。
  - 关联价格、最近更新为只读信息。
- 状态与保护：右上与底部各有一个状态标签（未保存 / 已保存）；「还原」回到上次保存内容；有未保存修改时返回列表会弹确认框，避免误丢。
- 保存：写回 `ampg:demo:v1` 的 `standards`，同时把 `updatedAt` 更新为当天，提示「标准物料已保存，价格匹配与询价将使用新内容」。

### 9.5 规格级历史叫法（属性同义词）

标准和价格匹配最容易出错的地方是「历史文件写法不同、其实是同一规格属性」。因此在标准物料这一侧，同义词分两级维护：

| 级别 | 存储位置 | 作用 |
|------|----------|------|
| 规格级（属性同义词） | `StandardMaterial.attributeSynonyms[label]` | 「牌号」也写成钢种 / 牌号等级；「直径」也写成规格 / Φ径 / 断面直径 |
| 商品级（整条物料的别名） | `StandardMaterial.synonyms` | 整条物料在历史文件里的其它叫法，可以有多条 |

- 交互：每条规格行下方缩进对齐一行「历史叫法」；「+ 添加」在原地展开小输入框（占位符带出该属性名的常见写法，如 `如 钢种`），回车或失焦提交；Tag 上的 × 单条移除。行内编辑，不弹窗、不跳页。
- **防误归并**：同一个叫法已登记在另一条规格下时，先弹确认框「该叫法已登记在其它规格下」，说明它目前属于哪个规格、继续添加表示要归并到当前规格；取消则不写入。
- 快速添加（点「+ 牌号」这类标签）时，会按 `defaultAtomSynonyms` 自动带出该属性名的常见历史写法，不用手工敲。
- 保存时 `attributeSynonyms` **整体重建**而非合并：规格行改名后同义词自动迁到新键、旧键不残留；某条规格的叫法删光后该键消失。因此读取侧一律 `attributeSynonyms?.[属性名] ?? []`。
- 与治理工作台一致：治理台确认入库时写入的就是这个字段，编辑页与治理台读写同一份数据，不会互相覆盖或丢字段。

## 10. 编制采购清单：附件解析与引用

「附件」不再是占位按钮，而是一条真实链路：**上传 Excel → 浏览器端解析 → AI 识别表头 → AI 匹配标准物料 → 引用回清单**。

### 10.1 上传与解析

- 入口：「采购清单」面板底部「添加附件」、工具栏「批量导入」，都指向同一个隐藏 `input[type=file]`（`accept=".xlsx,.xls"`），选完即开始解析，不经过服务端。
- 本期限制：仅 Excel（`.xlsx` / `.xls`），单文件 ≤30MB；PDF / CSV 仍走「数据接入清洗」页。非 Excel 文件直接提示并拒绝，不产生附件记录。
- 解析分五个阶段，每个阶段都写一行小字进度（`.pl-att-progress-text`），运行中额外显示 3px 细进度条与「停止」按钮：
  1. `parsing` 正在读取 Excel 文件…
  2. `parsing` 已解析工作表「X」 N 行 · M 列
  3. `mapping` AI 正在识别表头字段… → 字段映射完成（AI / 本地）· 物料名称列「…」
  4. `matching` AI 正在匹配标准物料 已完成/总数 · 第 i/n 批 · 本批命中 k 行
  5. `done` 解析完成 · N 行 · 命中标准物料 K 行 · 平均置信度 C · 耗时 T s
- 合计数、条款行由 `buildRawItems` 的 `isNoiseRow` 剔除，条数记入 `skipped`，在弹窗头部展示「已剔除 N 行非物料」。单次最多解析 30 行（`MAX_ITEMS`）。

### 10.2 AI 匹配（`ai/match.ts`）

- 候选库 = `context.standards`（标准物料库当前内容，含用户编辑结果）+ `initialPrices`（历史价格）。
- 每批 10 行，把候选压成 `编码｜名称｜品类｜规格:…｜别名:…` 单行文本随 prompt 发出，要求返回 `{idx, code, confidence, reason, gap}`：
  - 关键规格（牌号 / 直径 / 强度等级 / 公称直径 / 芯数截面 / 功率 / 砌块尺寸）冲突即判不匹配，允许 `code` 返回空；
  - 写法差异算同一物料（三级抗震螺纹钢20 = HRB400E Φ20mm），但必须在 `reason` 写归一依据；
  - `gap` 记录原文缺失项（如「原文未写牌号」），展示在展开区提示人工核对。
- **编码校验**：模型返回的 code 必须存在于候选库，否则按未匹配处理，避免编造编码。
- **失败降级**：单批调用失败不中断整体流程，该批改用 `matchLocally`（别名 50 分 + 品类词 20 分 + 规格数字 15 分/个，上限 85），进度文案会显式改成「AI 通道不可用，已改用本地关键词匹配」，不伪装成 AI 结果。
- token 约束：`maxTokens` 必须 8000（`deepseek-flash` 为推理模型，给少了正文为空）。

### 10.3 引用弹窗（`AttachmentQuoteModal`）

- 触发：附件条目完成后的「引用」链接。弹窗宽 1180。
- 头部：文件名 / 大小 / 工作表 / 有效行数 / 剔除行数，右侧三格统计（命中标准物料 x/y、平均置信度、解析字段「物料名称」）。
- 表格（行 = 附件解析行）列：勾选、序号、附件解析行（原文 + 规格小字）、数量/单位、含税单价、推荐标准物料（编码 + 标准名称）、规格型号（Tag 前 2 + `+N`）、置信度（数字 + 3px 色条：≥85 绿 / ≥70 蓝 / ≥50 橙 / 其余红）。
- 默认只勾选命中行，未命中行留给人工判断。
- 展开行（三栏）：
  - **推荐物料明细**：编码、标准名称、品类路径、规格型号 Tag、历史叫法；底部「指定物料」下拉可手工改（未命中行也能选），改完即生效。
  - **价格数据**：关联价格条数、历史均价、价格区间、最近成交日 + 最近 3 条价格记录（来源 / 单价 / 品牌·局·日期）。无记录时提示「暂无已审核的历史价格」。
  - **AI 判断依据**：`reason`、`gap` 差异提示、附件原文。
- 底部：`已选 x / y 行，其中 z 行已关联标准物料` +「取消」「引用选中行到清单」「全部引用」。

### 10.4 引用写回清单

- 名称、规格型号取**标准物料**（规格值去掉「指标名：」前缀后用 ` / ` 连接）；附件里没有标准物料时回落原文 `raw` / `spec`。
- 数量、含税单价取附件原文（非数字字符剔除，数量取整）；单位优先取附件。
- 合价 = 含税单价 × 数量；税率固定 13%，不含税单价/合价、税额按 13% 反算，统一 6 位小数。
- 「报价依据」写为 `附件引用`，品牌取该物料最近一条价格记录的品牌。
- 参考价按 `refPriceOf(标准物料编码)` 取，与价格分析页同源；该行未匹配到标准物料时用商品名称生成，仍保持稳定。
- 引用后弹窗关闭，清单行追加到末尾并提示「已引用 N 行到采购清单」。

### 10.6 静态导入约束（务必遵守）

- 不要引入 `?url` 资源；单文件产物只返回主 JS，外部 asset 在导出运行时 404。`ai/match.ts` 顶部已写明该约定。

### 10.8 清单草稿：去看参考价、再返回，数据不能没

问题出在切页方式上：点参考价「查看详情」是 `setPage('analysis')`，**清单页整个卸载**，`rows / attachments / listName / 建议栏` 都是组件内 `useState`，返回时重新挂载就回到初始那 4 条演示数据——用户刚解析引用的一屏行全没了，演示到这一步就断。

落地为独立草稿 `ampg:purchase-draft:v1`（不塞主快照：附件解析结果体积大，混进去会拖慢其它页面每次读写）：

- **读**：组件挂载时一次性 `useState(loadPurchaseDraft)` 读回；**有草稿就照草稿来**（草稿是空表说明用户主动删空了，不要再铺种子数据），没草稿才 `seedRows()`。
- **写**：变更后 300ms 防抖落盘（输入框不必每个键都序列化一次附件解析结果）；**卸载时无条件同步 flush 一次**——点「查看详情」正是先卸载，防抖定时器等不到。
- **保存按钮**变成显式落盘：「采购清单已保存：N 条明细、M 个解析附件，离开页面再回来还在」；本机存储不可用（隐私模式 / 配额满）时提示只在本页停留期间保留。
- **未解析完的附件**恢复时标成「解析中断，可移除后重新上传」：`AbortController` 随卸载失效，不这么处理进度条会永远停在 63% 骗人。
- 类型带 `version: 1`，结构升级直接回落到无草稿；`clearDemoState()` 一并清掉这个 key，「重置演示数据」后回到 4 条种子。

## 11. 参考价与价格分析（`analysis`）

业务诉求：编制采购清单时每行都要知道「这东西大概什么价」，而且这个价不能凭空给一个数——得能点进去看它过去招采过几次、和谁签的、签在什么价位。所以这一章是两件强耦合的事：清单上的参考价列，和承载依据的价格分析页。

### 11.1 采购清单：参考价列

- 位置：「报价依据」之后、「含税单价」之前。阅读顺序是「依据 → 参考价 → 我的报价」，比的逻辑才顺。
- 单元格两行：
  - 第一行：参考价金额（千分位 + 2 位小数）+ 计价单位，右侧是**相对当前含税单价的偏离**（`+0.8%` 暖色 / `-1.3%` 绿色 / `持平` 灰）。
  - 第二行：参考日期（`09-28`）+ 有效样本数（`38 个样本`），右侧「查看详情 →」。
- 表头 Tooltip 说明口径，避免被当成固定指导价。
- 「查看详情」调用 `openPriceAnalysis(subject)`：把商品名、规格、单位、标准物料编码（并在命中标准物料时附上属性原子与品类）带进 context，再切页到 `analysis`，**不是新开页面也不是弹窗**。
- 偏离色只用两种：高于参考价用暖色（成本上浮要提醒），低于用绿色，与国内涨跌配色一致。
- 清单初始预置 4 条模拟数据（钢筋 Φ25 / 水泥 P.O42.5 / 钢筋 Φ20 / 焊管 DN100），一进页面就能看到参考价与穿透入口；删完仍回到「暂无数据」空态。

### 11.2 参考价的来源与口径（`analysisData.refPriceOf`）

- 单一来源：`refPriceSeed`，逐条写明 `price / unit / source / date / samples`，数值与 `initialPrices` 的历史成交价对齐（清单写 3860 的钢筋，分析页也得是 3860）。
- 未登记的物料按计价单位的常见量级生成（吨 300~4500、米 12~190、个 18~900…），种子取商品标识哈希，**同一物料永远同一个价**，不会刷新一次变一个数。
- 口径文案三种：`近 6 个月合同加权` / `近 3 个月合同均价` / `近 6 个月合同加权`（历史合同不足时回落）。
- 参考价与「当前报价」是两个概念：参考价是市场参照，报价是这一单的成交意图，页面上从不混用。

### 11.3 价格分析页结构

自上而下：

1. **筛选卡片**：分析商品下拉（标准物料库全量，带编码）+ 组织机构 + 专项区域 + 时间范围（近 6 / 12 / 24 个月 / 全部）+ 查询 / 重置。筛选采用「点查询才生效」的两段式，改条件后出现「筛选条件已修改，点『查询』生效」提示。
2. **商品条**：一行三列（列头是小号灰字标签），右侧突出「参考价」大字 + 来源 / 日期 / 样本数。
   - **商品名称**列：名称 + 下方一行标准物料编码与品类路径。
   - **单位**列：计价单位（吨 / 米 / 个…），下方注明「按此单位计价」。
   - **规格型号**列：与标准物料库、治理工作台一致，展示属性原子 KV 标签（`牌号：HRB400E`、`直径：Φ25mm`…），列头带「N 个属性」计数；没有属性原子时退回按分隔符拆开的值标签，两者都没有才显示「未登记规格型号」。
   - 规格型号取 `subject.attrs`（属性原子原文），不是 `subject.spec`（只留属性值的拼接串）。采购清单「查看详情」会先按 `materialCode` 回查标准物料，把 `attributes` 与 `category` 一起带进分析页。
3. **4 个关键指标**：参考价、区间成交均价（跟随时间范围改标题）、累计签订合同（附覆盖分供商数与区域数）、累计合同金额（附单价区间）。
4. **采购合同金额走势**：按月，柱 = 合同金额（万元），线 = 成交均价（元/单位），双纵轴。
5. **区域合同金额分布**（左）+ **工程局金额占比**（右）：前者是金额降序排行（名次 / 条形 / 金额 / 占比 / 份数），后者柱 + 占比线。
6. **年度采购金额与结构占比**：用全部合同（不受时间筛选影响），体现逐年价格与规模变化。
7. **数据详情表**：合同编号（附「合同 / 招标清单」来源标）、采购项目、分供商、签订日期、**与参考价**、数量、单价、合同金额、区域 / 工程局、操作「查看合同」；分页 10 条，支持关键词搜索。

### 11.4 数据自洽与筛选

- 所有图表、KPI、明细表都从**同一份合同明细**聚合，不是各自造数——所以「区域占比合计 100%」「明细条数 = 累计签订合同数」永远成立。
- 合同集用确定性伪随机（`mulberry32` + 商品标识哈希）生成：近 24 个月每月 5~8 条 + 更早历史 16 条。
- **工程局与区域按序号轮转分配**，不是纯随机：纯随机会让按单个工程局筛选时某些月份一份合同都没有，走势图出现空洞。
- 单价随「距今年限」缓慢上抬（每年约 -3% 的历史折价 + ±4% 个案波动），所以年度图是一条温和上行的价格线，与月度走势同一口径。
- 筛选后某月无合同时，折线在该处**断开而不是连到 0**，否则曲线会一头扎到底再弹回来，看起来像价格崩盘；只有全部月份都有值时才会画面积填充。

### 11.5 图表实现约束

- 图表是**手写 SVG**（`analysisCharts.tsx` 的 `ComboChart` / `BarRank`），**不引图表库**：
  - 单入口 iife 导出禁动态导入，而图表库动辄几百 KB、只在这一页用；
  - 形态固定（柱+双轴线、横条排行），手写更可控，配色与页面完全一致。
- 尺寸用 `ResizeObserver` 取容器实测宽度再按真实像素画，不用 `viewBox` 缩放——否则文字会被拉大或压扁。
- 坐标轴上界走 `niceStep`（1 / 2 / 2.5 / 5 / 10 倍数），折线默认不从 0 起（价格从 0 起会压成直线），可按 `lineFromZero` 切换。
- 折线用 Catmull-Rom 转三次贝塞尔做平滑，点是白心描边圆点，SVG `<title>` 提供原生悬停提示。
- **区域分布不用地图**：地图涉及地理数据合规与边界准确性，改用金额排行条，信息量等价且没有合规风险。

## 12. 智能询价（`inquiry`）

业务诉求：编制清单时手上常常先有一份**供应商报价**，需要快速回答「这个价贵不贵、值不值得谈」。所以这一页不是再做一个价格看板，而是「拿报价来问价」——输入一份清单或报价表，系统给出每行的判定与依据，并能一路穿透到这件商品的历史签约明细。

### 12.1 两种输入

| 输入方式 | 链路 | 说明 |
|----------|------|------|
| 粘贴清单 | 按行正则解析 → 匹配标准物料 → 比对 | 每行「名称 规格 数量 单价」，支持 `120吨`、`3980元/吨`、`¥3,980` 写法；从行尾往前剥报价、再剥数量，剩下的是物料名称 |
| 上传报价表 | `parseFile` → 表头映射（AI 优先 / 本地兜底）→ `buildRawItems` → 匹配 | 支持 xlsx / xls / csv / pdf；Excel 走表头映射，PDF 走文本行。合计行、条款行、落款行照样剔除 |

- 单次上限 30 条（沿用 `MAX_ITEMS`），保证演示耗时可控。
- 上传后「来源」列记文件名，粘贴记「手工录入」，方便区分一单里混着的多份报价。
- 两个入口共用同一套匹配（`matchRowsWithAi`，每批 10 条），AI 不可用时整批降级为本地关键词匹配，进度文案会**如实写「模型通道不可用，已改用本地关键词匹配」**，不冒充 AI 结果。

### 12.2 判定口径：区间，不是单点

- 参考价 `refPriceOf` 与采购清单、价格分析同源；**判定看的是 P25~P75 的成交区间**（`priceProfileOf` 从同一份历史合同集算分位数），不是拿单点参考价比大小——成交价本来就有波动，比单点会把正常浮动误判成「贵」。
- 分级：超出区间上沿 = 偏高，超出 10% = 明显偏高；破下沿 = 偏低，破 10% = 明显偏低；区间内 = 合理。
- 偏离列仍给「相对参考价的百分比」，因为业务看报价单的习惯还是盯基准价。
- **单位不一致不硬算**：报价单位（米）与物料计价单位（吨）不同时，判定列直接显示虚线框「单位不一致」，偏离留空，并在悬停提示里写明两个单位。折算率属于采购口径，原型不猜。
- **单位先归一，再比**：报价表里钢材写 `t`、清单里写「吨」，电缆写 `m`、清单写「米」。直接比字符串会整列误报「单位不一致」（演示时上传一份正经报价表却满屏红字，像系统坏了），所以 `inquiry.sameUnit` 先做同义归并（t↔吨 / kg↔千克↔公斤 / m↔米 / m2↔㎡↔平方米 / m3↔m³↔立方米 / 只↔个），**只归并不换算**，不认识的单位仍按不同处理，交给人工核对。
- **没报价就不给结论**：报价为空时偏离列显示「—」而不是「偏离 0% / 持平」，也不计入「高于区间占比」与「平均偏离」的分母——没报价就没有偏离可言。
- 「可议价空间」只统计**明显偏高且写了数量**的行，按（报价 − 参考价）× 数量估算，不把区间内的正常波动算成可省的钱。

### 12.3 页面结构

自上而下：询价输入（粘贴 / 上传两个页签）→ 参考口径（组织机构 / 专项区域 / 取价范围，两段式「重新取价」生效）→ 4 个指标（询价条目 / 成功匹配 / 报价高于成交区间 / 可议价空间）→ 询价结果表 → 口径说明脚注。

结果表列序（关键对比列前置，1440 宽下首屏就能看完「是什么 + 贵不贵」）：序号 / 询价物料（含数量与来源）/ **规格型号**（属性原子 KV）/ 报价单价 / 参考价 / 偏离 / **判定** / 匹配标准物料（名称 + 编码）/ 匹配度 / 参考区间 / 样本 / 操作（价格分析 · 提交治理，`fixed: 'right'`）。

**规格型号列的口径**（业务方 2026-10-25 补的要求：询价结果里没有规格型号，看不出这条报价到底是什么东西）：

- **已匹配的行**取该标准物料已登记的 `attributes`，按 `属性：属性值` 逐条渲染成 KV pill（与标准物料库、价格分析、物料映射同一套口径），属性名灰色、属性值深色加粗，一行 2 个 pill 自动换行，最多 4 条（钢筋/管材/电缆/砌块都是 4 条）。
- **未匹配的行**不给假规格：有报价单里的规格原文就显示原文（两行截断 + Tooltip 全文），没有就显示「未登记规格」。
- 列宽 204px 是算过的：序号 48 + 询价物料 208 + 规格型号 204 + 报价 108 + 参考价 100 + 偏离 80 + 判定 92 = 840，再加匹配标准物料 244 = 1084，仍小于「容器宽 − 固定操作列 168」，所以 1440 宽下首屏既能看到规格型号，匹配标准物料也不会被固定列压掉一半（早前 216px 版本的第一个副作用就是它）。

### 12.4 与价格分析的联动

- 每行「价格分析」→ `openPriceAnalysis(subject, 'inquiry')`，带上标准物料的名称、规格型号（属性原子 KV）、单位、品类。
- 价格分析页的返回按钮读 `analysisFrom`：从询价进来是「返回智能询价」，从清单进来仍是「返回采购清单」。这个来源只存在内存里，刷新后回默认（清单）。
- 询价结果落 localStorage `ampg:inquiry:v1`（version + try/catch 静默降级）：**切页会把页面卸载**，不存的话点完「价格分析」再返回，手上的单子就没了。顶部「清空重来」同时清快照。

### 12.5 顺手修掉的两个既有问题

- `refPriceOf(key)` 原本默认 `unit = '吨'` 并覆盖种子单位的返回值，导致价格分析页下拉里「YJV 电缆」被标成 96.5 元/**吨**。现在只有显式传 unit 才覆盖，种子自带单位优先。
- 参考区间在样本极少时 P25 = P75 会画成一条线（页面上看不出区间），补了 ±3% 的窄带兜底。

## 13. 物料映射（`material-mapping` + `mapping-detail`）

业务诉求：历史招标清单里的物料是**非标写法**（「三级抗震螺纹钢 25 定尺9m」「普硅水泥 42.5 袋装」），标准物料库里是**标准口径**（`HRB400E 热轧带肋抗震钢筋 Φ25mm`）。两边不挂钩，历史上那么多真实成交价就只是一堆死文本，价格分析和智能询价都用不上。所以这一章解决的是「**把历史清单一条条认到标准物料上**」，认完之后历史价才按标准口径可复用。

### 13.1 一对多关系（先定清楚）

| 关系 | 说明 |
|------|------|
| 一条标准物料 ← 多条历史写法 | 「三级抗震螺纹钢25 定尺9m」「HRB400E Φ25 盘螺」「螺纹钢25（三级）」都可以认到同一条 `STD-GJ-000129` |
| 一条历史清单项 → 至多一条标准物料 | 清单项是采购事实，只能有一个标准口径；要改就改判，不能同时挂两条 |
| 映射 ≠ 建档 | 已存在的标准物料只做关联；标准库确实没有的（如「铝合金桥架」）走「标记为新物料，转治理建档」，**不在本页新建标准物料** |

因此页面上必须显式回答「这条标准物料已经被多少条历史写法认过」——右侧面板的「同一标准物料的其它历史写法（N 条）」就是干这个的，避免经办人以为是新建档而不敢下手。

### 13.2 两级页面与状态机

- **一级：招标列表**（`material-mapping`）。列：招标编号 / 招标项目（含品类 Tag、区域、采购方式）/ 采购组织 / 开标日期 / 清单条数 / **映射进度**（三段进度条：已确认 · 待复核 · 未映射，文案形如 `6/12 条 · 待复核 4 · 转治理 1`）/ **可复用历史价**（条数 + 万元）/ 状态 / 操作（「映射」进工作台，「已映射」时为「查看」）。整行可点。默认按开标日期倒序。
- 顶部一条 `.mp-note` 说明「标准物料与非标是一对多…」并回显全局待复核条数与清单项总数；4 个 KPI：历史招标项目 / 待复核映射 / 已映射清单项 / 可复用历史成交价（条数与涉及金额）。
- 筛选：状态分段（全部 / 待映射 / 映射中 / 已映射）+ 年份 + 关键词（招标编号、项目名称、采购组织、区域）。
- **二级：清单映射工作台**（`mapping-detail`，隐藏页，从行进入；`activeBidKey` 记住当前招标）。
- 单条清单项状态机：`todo 未映射` → `pending 待复核`（系统预映射或人工选定但未确认）→ `done 已确认`；另有一支 `new 转治理建档`（标准库无相近物料）。项目状态由条目聚合：全部未映射 = 待映射，有已确认但未完成 = 映射中，全部处理完 = 已映射。

### 13.3 进项目就自动预映射（不给一张空表）

- 首次进入某个招标时调 `autoMapProject`：逐条拿候选打分，最高分 ≥ `AUTO_MAP_THRESHOLD`（68）就直接落一条「待复核」映射，并 `message.info` 告知「已按历史叫法与规格属性预映射 N 条，逐条复核后提交」。
- 已存在映射的条目跳过（`onlyMissing`），所以刷新、离开再回来都不会把人手工改的结果冲掉。
- **预映射一律是「待复核」不是「已确认」**：机器给的是建议，金额能不能复用要人点头。
- 内置演示把两种进度都做出来了：`ZB-2024-06104` 全确认（列表显示「已映射」、可复用价 270.3 万元），`ZB-2024-08812` 前 6 条确认、其余待复核（进度 6/12，可复用 6 条 899.2 万元），其余 4 个招标未映射。

### 13.4 规格型号：默认解析、可改、带来源

用户原话是「映射上之后要补充规格型号，但是我们会默认进行解析，帮他映射上，他也可以修改」。落地为三层：

> 先分清两个东西：**历史规格型号**是招标清单里那串自由文本（`BidItem.spec`，如 `25 定尺9m`、`4x25+1x16 铜芯`），只用于展示和作为解析输入，各家写各家的、不追求干净；**映射后的规格型号**才是要写进标准物料的结构化 `属性名：属性值` 行（`MappingRecord.attributes`），必须口径统一。三层来源说的是后者。

1. **沿用**（来源标 `standard`）：目标标准物料自己登记的规格属性，原样带出，不需重填。
2. **解析**（来源标 `ai`）：`parseBidSpec(原始描述)` 按品类从历史写法里抠出属性，标准侧没登记的追加进来。已覆盖钢筋（牌号 / 直径 / 外形 / 特性 / 定尺长度，认「三级」「盘螺」「HRB400E」）、水泥（强度等级 / 类型 / 包装）、管材（公称直径 / 材质 / 表面处理 / 连接方式）、电缆（型号 / 芯数截面 / 材质 / 电压等级）、砌块（长高厚 / 强度等级）、砂（品类 / 粒径 / 细度模数）、灯具（功率 / 灯头口径 / 色温，「暖白」归一到「暖光」）。**解析不出来就老实返回空**（成品门、断桥窗、桥架这类描述里没有可结构化拆的属性），不编。
3. **手工**（来源标 `manual`）：面板里每行可改属性名与属性值，可删行，可「补充一条规格型号」；改过即标为手工，来源列一眼能看出这条是人填的。

- 确认前校验：属性行留空的会被拦住（提示「有 N 条规格型号没填完整」）；批量确认与提交时会**过滤掉空行**再落库，不会把空 label/value 写进快照。
- KV 口径与标准物料库、治理工作台一致：`属性名：属性值`，同一个商品行里多行竖排，不是多条商品行。

### 13.5 推荐候选：可解释的打分

`recommendStandards(item, standards, prices, mapping)` 在本地算，不依赖模型通道，保证演示可复现、可离线：

- 逐属性对比得出 `same / diff / missing / extra`（当前历史描述 vs 标准物料），**只按双方都声明的属性算平均相似度，再乘覆盖度系数**（`0.7 + 0.3 × 覆盖度`）。这一点踩过坑：早前把「标准侧多出的属性」当分母惩罚，导致 Φ25 只有 60% 分、08812 十二条只映射上一条——标准侧规格更全本来就是好事，不该扣分。
- 总分 = 属性一致度 × 0.62 + 名称 Dice 二元组相似 × 0.18 + 命中该标准已登记历史叫法 × 0.1 + 品类命中 × 0.1；再对「无任何属性冲突且至少对上 2 项」的强证据 +10，上限 99。
- 取前 4 个、≥35 分的候选；每个候选带 `compare`（逐属性对照）、`reasons`（人话理由，如「牌号与直径完全一致」「命中历史叫法『三级抗震钢25』」）、`linked`（这条标准已被哪些历史写法认过）以及历史价格水位。
- 面板呈现：34px 分数块 + 标准名称与编码 + 「已关联 N 条历史写法」+ 历史价 + 逐条属性对照（一致/差异/缺失染色）+ 前两条理由。分数、理由、对照三者都在，经办人才敢点确认。
- **没有候选时明确说没有**：显示「标准库没有相近物料，建议标记为新物料，带着解析结果去治理台建档」，并给「标记为新物料，转治理建档」按钮（`by: 'new'`），不硬凑一个低分候选。

### 13.6 工作台布局与操作

- 头部信息条：清单条数 / 已确认 / 待复核 / 未映射 / 转治理建档 + 覆盖率进度 + 「已归集历史成交价 N 条 · 金额」。
- 工具栏：分段筛选（全部 / 未映射 / 待复核 / 已处理）+ 搜索 + 「一键预映射」「批量采纳推荐」「批量确认 N」。
- 左表列：# / **商品名称** / **规格型号** / **历史单价** / 映射到标准物料（标准名称 + 编码、品类与来源 Tag）/ 匹配度 / **状态（`fixed: 'right'`）**。**按 `idx` 升序固定排序**，不做状态排序——纸质清单是要逐行对账的，序号一跳就没法核。
  - 商品名称与规格型号是**两列**：历史清单里这两件事本来就是分开写的（「三级抗震螺纹钢」是名，「25 定尺9m」是规格尾巴），挤在一列里经办人还得自己做切分。
  - **历史的规格型号只是一段文本字符串**，不是标准库那种结构化属性键值对——各家写法不一（`25 定尺9m` / `HRB400E Φ25` / `Φ25 HRB400E`），所以这一列按纯文本排，不渲染 KV chips；结构化是「映射」这一步的产物（见 13.4 与右面板），不能拿它假装历史数据本身干净。清单没写规格时标灰字「未写规格」。
  - **不设数量列**：数量对「这是不是同一件物品」的判断没有帮助，只会挤掉规格与映射结果的宽度；历史单价保留（`¥3,810.00` / `元/吨` 两行），因为价格水位是选标准物料时的参考。
  - 状态列钉在右侧：1440 宽下本表约 860px、可视约 780px，窄屏必然横滚，而「待复核 / 已确认」是决定「这条能不能提交」的关键信号，必须常驻可见（固定列补了底色与阴影，避免与横滚内容糊在一起）。
- 右侧 sticky 面板：未映射时是「解析属性 → 推荐候选 → 转新物料」；已映射时是「映射到哪条（可撤销映射）→ 映射后补充的规格型号（可编辑）→ 这条历史叫法 → 同一标准的其它历史写法 → 确认此项映射 / 撤回确认」。
- 确认后自动跳到下一条未处理项，连续处理不用回表点。
- 「提交映射结果」走二次确认，写清「将确认 N 条待复核映射；另有 N 条仍未映射，会保留在待处理里」，提交后回招标列表。

### 13.7 统计与持久化

- `projectStats`：总数 / 已确认 / 待复核 / 转治理 / 未映射 / 可复用条数 / 覆盖率 / 金额。**金额只统计「已确认且挂了标准物料」的条目**——未确认的是建议，新物料还没进标准库，都不能算成可复用历史价。

### 13.9 与其它页面的口径关系

### 14.2 七步闭环（与菜单同序）

七步 = 数据接入清洗 / 专家任务 / 专家组装 / 运营入库审核 / 标准物料库 / 采购与映射应用 / 智能询价，每步一张卡：序号 + 状态词 + 名称 + 主指标 + 两行说明。

- 状态四态：`ok` 已就绪 / `doing` 在推进 / `attention` 有积压（橙色描边，卡点必亮）/ `todo` 还没开始（虚线灰）。
- 头部只报两件关心的事：「待启动 N 步 · 积压 N 步」，不报笼统的「完成度」。
- 主指标依次为：导入批次数 / 任务数 / 组装完成率（任务 `completed/total` 汇总）/ 待审核条数 / 标准物料数 / 历史清单映射覆盖率 / 询价匹配行数。
- 卡片可点，直达对应页面。

### 14.3 下一步建议 + 四个卡点

按业务优先级取第一条命中的作为「下一步建议」，标题写清「卡了几条、卡在哪」，描述写清「为什么现在必须处理」：

1. 有待审核 → 「N 条组装结果卡在入库审核」（新增建档 x / 修改已有 y）→ 去审核
2. 有驳回 → 「N 条组装结果被驳回，等专家改完重提」→ 去治理工作台
3. 没有导入批次 → 「闭环还没开始：先接入一批数据」→ 接入数据
4. 历史清单还没映射完 → 「N 条历史清单还没认到标准物料上」→ 去物料映射
5. 没询价过 → 「链路已跑通，去询价看看效果」→ 发起智能询价
6. 都没事 → 「闭环畅通：标准库与历史价都在持续沉淀」→ 看标准物料库

下方四格固定报「待审核提交 / 驳回待重提 / 逾期任务 / 未映射清单」，为 0 置灰、>0 标橙，每格可点。

- **治理任务与进度**：任务名（含「导入」标记）、来源（文件名与物料条数，手建的写「手工创建」）、进度条 + `completed/total`、待审核数、状态、操作（去处理 / 继续治理 / 去审核 / 看成果）。

### 14.6 已知边界

- 「治理队列 `pendingCount`」初始 1,287 条是演示用的历史积压口径，只有「导入 +N」「审核通过 -1」两条链路会动它；它与标准物料库列表（15 条）不是同一个口径，不要混着念。
- 询价 KPI 读的是询价页写下的快照，**当页不做实时订阅**：在询价页跑完再回总览才会更新（切页会重新挂载，够用）。
- 品类构成按「中间一级」分组；只有一级的品类（如只写「灯具」）会自成一列，这是数据写法决定的，不做猜测性归并。
