# 分供商是否存在有效考察报告（规则页迭代）

> 本文档仅记录**本次迭代**的新增内容，供研发评审使用。页面整体结构、左侧规则树、公共配置项、明细表格的公共列等通用能力均由组件 [risk-rule-config-page](file:///Users/liurundong/Desktop/云端演示项目/LRainD.github.io/axureMake/src/components/risk-rule-config-page/index.tsx) 提供，不在本文展开。

## 一、迭代目标

在风控预警中心「规则管理」下新增一条规则页：**校验分供商是否存在有效的考察报告**，无有效考察报告时触发预警/拦截。

## 二、规则信息

| 项 | 值 |
|----|----|
| 规则名称 | 分供商是否存在有效考察报告 |
| 规则说明 | 校验分供商是否存在有效的考察报告，无有效考察报告将会预警/拦截 |
| 默认开关 | 开 |
| 挂载位置 | 规则树「招投标」分组，默认选中本规则 |
| 规则 key | `supplier_inspection_report_check` |

## 三、专有配置列（本次迭代重点）

在明细表格公共列之后追加 3 个必填列，顺序与截图一致：

### 1. 是否开启校验

- 控件：`Switch` 开关
- 交互：开 / 关（`checkedChildren="开"`、`unCheckedChildren="关"`）
- 默认值：开

### 2. 校验阶段

- 控件：`Select` 下拉多选
- 选项：报名资审 / 定标/成交报告
- 默认值：报名资审

### 3. 是否校验组织、范围（可多组，竖向排列）

- 列 key：`checkOrgScope`
- 布局：列内可设置**多组**「组织 + 范围」，每组占一小行，竖向排列；每行右侧带删除图标，列底部为「添加」按钮
- 交互：点击「添加」在该列末尾追加一行（组织 + 范围，均为空）；点击行尾删除图标移除该行；首行为默认行

| 行内元素 | 控件 | 数据 / 选项 | 默认值 |
|----------|------|-------------|--------|
| 组织 | `TreeSelect` 组织选择树 | 以「中国建筑股份有限公司」为根节点，演示包含四局（第一建设、第二建设、安装工程、建设发展）、二局、三局等下层级组织 | 空 |
| 范围 | `Select` 下拉单选 | 本级 / 本下级 | 首行默认「本下级」，新增行为空 |

- 组织控件交互：`treeCheckable` 树形多选，`showCheckedStrategy=SHOW_PARENT`（选中父节点即代表其下全部子节点）
- 组织下拉面板宽度不跟随输入框（`popupMatchSelectWidth=false`），面板最小宽度 320px，避免组织全称换行

> 组织 + 范围共同确定「有效考察报告」的判定范围：系统在所选组织的「本级」或「本级 + 下级」范围内校验分供商是否存在有效考察报告；支持配置多组，满足后即视为通过校验。

## 四、规则配置项取值

本次迭代沿用组件公共配置项，取值如下（供评审确认）：

| 配置项 | 取值 |
|--------|------|
| 适用组织范围 | 本下级 |
| 下级独立配置 | 不允许 |
| 预警级别 | 中风险 |
| 是否去重 | 不去重 |
| 规则类型 | 合规风险 |

## 五、接入方式

整页复用 `RiskRuleConfigPage`，本次仅传入以下规则差异项：

| Prop | 值 |
|------|----|
| `ruleName` | 分供商是否存在有效考察报告 |
| `ruleDescription` | 校验分供商是否存在有效的考察报告，无有效考察报告将会预警/拦截 |
| `defaultRuleEnabled` | `true` |
| `config` | 见上表 |
| `extraColumns` | 是否开启校验（开关）、校验阶段（下拉多选）、是否校验组织、范围（可多组「组织 + 范围」，支持添加 / 删除） 共 3 列 |
| `treeData` | 组件默认规则树 + 「招投标」分组追加本规则 |
| `defaultSelectedRuleKey` | `supplier_inspection_report_check` |
| `tableScrollX` | `2050` |
