# 1. 需求背景

## 1.1 问题描述

1. “开启采购”弹窗中的“合作品类”是必填项，目前只能从下拉列表中凭经验选择，共 5 个合作品类，名称相近、边界容易混淆。
2. 采购经办人在填写招采名称时，名称里往往已经包含“混凝土”“钢筋”“电缆”“模板”等明确的品类信息，但系统没有利用这些信息辅助判断。
3. 选错合作品类会连带影响后续采购品类、供应商范围、统计口径，产生退回、修改和重复沟通。
4. 新入职经办人对品类不熟悉，通常需要询问老同事或品类管理员，判断成本高、口径不统一。

## 1.2 目标用户

| 用户角色 | 角色特征 | 核心诉求 |
|----------|----------|----------|
| 采购经办人（主要） | 在集采工作台发起采购任务，需要填写合作品类、采购品类等基础信息 | 少记品类、少判断，快速选对合作品类 |
| 采购品类管理员（间接） | 维护合作品类口径，解答一线品类咨询 | 减少因品类选错带来的咨询和返工 |
| 采购负责人（间接） | 关注采购任务质量与统计准确性 | 品类口径统一，数据可追溯 |

## 1.3 业务目标

本期建议以以下指标衡量效果：

1. 智能推荐合作品类的采纳率 ≥ 60%（点击“立即使用”的次数 / 点击“立即推荐”的次数）。
2. 因合作品类选择错误导致的退回、修改量下降 30%。
3. 单次合作品类判断耗时由平均 30 秒降至 5 秒以内。
4. 推荐未匹配时，100% 提供“可点击申请添加 >>>”的补库入口，并在当前页面弹出“申请新增合作品类”弹窗，形成品类库扩充闭环。

# 2. 产品定位

## 2.1 产品定义

在“开启采购”弹窗内，根据经办人填写的招采名称智能识别并推荐合作品类，经经办人确认后一键回填的辅助填写工具。

## 2.2 核心价值

1. **少记忆**：不需要背 5 个合作品类的边界和适用范围。
2. **少判断**：系统给出推荐结果和命中依据，经办人只需确认。
3. **少返工**：降低选错品类带来的退回、修改和沟通成本。
4. **可解释**：展示推荐所依据的关键词，让结果“看得懂、敢采用”。
5. **可补库**：未匹配时直接引导到合作品类库申请添加，避免流程中断。

## 2.3 产品差异化

| 对比维度 | 现状（人工下拉选择） | 本期方案（智能推荐浮窗） |
|----------|----------------------|--------------------------|
| 判断依据 | 依赖个人经验 | 依据招采名称中的品类关键词，结果可解释 |
| 操作路径 | 逐个浏览下拉选项 | 输入名称后一键推荐，再一键采用 |
| 填写打断 | 无需切换，但容易选错 | 浮窗叠加在当前弹窗上，已填内容不丢失 |
| 未匹配场景 | 无引导，只能凭经验猜 | 明确提示未匹配，并引导到合作品类库申请添加 |
| 结果可控 | 人工决定 | 系统只推荐、不自动填值，必须经办人点击“立即使用” |

# 3. 用户故事

## US-01 匹配成功并一键采用

作为采购经办人，
在开启采购、填写合作品类时，
为了快速选对合作品类、减少人工判断，
需要系统根据招采名称推荐合作品类，并支持一键回填。

**验收标准**

1. 在“开启采购”弹窗中，点击“合作品类”右侧的“智能推荐”，右侧滑出“智能推荐合作品类”浮窗；原弹窗及已填内容保持不变。
2. 输入招采名称后点击“立即推荐”，按钮进入“推荐中…”状态，推荐完成后在浮窗内展示推荐结果、命中关键词和“立即使用”按钮。
3. 点击“立即使用”后，浮窗关闭，推荐结果回填到“合作品类”下拉框；该字段原有的校验错误提示同步清除。
4. 回填后“合作品类”字段短暂高亮提示，并出现“已采用推荐合作品类：XXX”的轻提示。

**实现要点**

- 推荐结果只做展示，不自动写入表单，必须由经办人确认采用，避免覆盖已选品类。
- 命中多个合作品类时，取“命中关键词总长度最大”的品类作为唯一推荐结果。
- 回填后保留弹窗内其他已填字段。

## US-02 未匹配时引导补库

作为采购经办人，
在系统无法从招采名称识别出合作品类时，
为了不中断采购发起流程，
需要看到明确的未匹配提示，并能前往合作品类库申请添加。

**验收标准**

1. 推荐后无任何命中的，结果区展示“未匹配到”，并说明“合作品类库中暂无与本次招采名称匹配的品类”。
2. 文案中提供“前往合作品类库申请添加”入口，点击后进入合作品类库申请添加流程。
3. 未匹配时不影响当前“开启采购”弹窗的继续填写和提交（合作品类仍需人工选择）。

**实现要点**

- 合作品类库的申请、审核流程由合作品类库承接，本期只负责入口跳转，不实现申请表单。
- 原型阶段以轻提示示意跳转，正式实现需替换为真实跳转。

## US-03 修改名称后重新推荐

作为采购经办人，
在推荐结果不符合预期时，
为了得到更准确的结果，
需要修改招采名称后重新发起推荐。

**验收标准**

1. 修改招采名称后，上一次的推荐结果与错误提示立即清除，避免展示过期结果。
2. 可重复点击“立即推荐”，每次以当前输入内容重新推荐。
3. 推荐过程中按钮禁用，不可重复触发；按回车键同样不能重复发起。

**实现要点**

- 推荐中状态必须阻止重复提交，避免结果错乱。
- 输入内容变化即视为“结果过期”，必须清空旧结果。

## US-04 不打断采购信息填写

作为采购经办人，
在填写开启采购信息的过程中使用智能推荐，
为了不重复录入，
需要推荐浮窗不覆盖、不清空我已经填写的内容。

**验收标准**

1. 关闭推荐浮窗（关闭按钮、Esc 键、点击弹窗外遮罩）后，开启采购弹窗仍停留在原位置，已填内容不丢失。
2. 采用推荐结果后，仅更新合作品类，组织机构、组织形式、采购方式、采购品类等字段保持原值。
3. 同一时间只展示一个推荐浮窗；从合作品类推荐切换到采购品类推荐时，前一个浮窗关闭。

**实现要点**

- 推荐浮窗与开启采购弹窗为叠加关系，浮窗关闭不触发弹窗关闭。
- 关闭顺序：存在推荐浮窗时，Esc 键和遮罩点击优先关闭浮窗；再次操作才关闭开启采购弹窗。

# 4. 功能清单

## 4.1 核心功能模块

| 模块 | 功能点 | 优先级 | 功能描述 |
|------|--------|--------|----------|
| 推荐入口 | 合作品类行“智能推荐”入口 | 高 | 在开启采购弹窗的合作品类字段右侧提供文字按钮，点击打开推荐浮窗 |
| 名称录入 | 招采名称输入与示例填入 | 高 | 必填输入，最多 100 字；提供示例名称和“填入示例”快捷操作 |
| 智能推荐 | 关键词识别与品类推荐 | 高 | 根据招采名称匹配合作品类关键词，输出唯一推荐结果及命中依据 |
| 结果采用 | 一键回填合作品类 | 高 | 点击“立即使用”将结果回填到合作品类下拉框并关闭浮窗 |
| 未匹配引导 | 补库入口 | 高 | 未匹配时提示并引导前往合作品类库申请添加 |
| 状态与反馈 | 校验、推荐中、成功提示、高亮反馈 | 中 | 空输入校验、推荐中禁用、回填高亮、轻提示 |
| 关闭与互斥 | 关闭方式与浮窗互斥 | 中 | 关闭按钮、Esc 键、遮罩点击；与合作品类、采购品类推荐浮窗互斥 |
| 演示开关 | 匹配/未匹配结果切换 | 仅原型 | 仅供原型演示两种形态，正式实现不提供该开关，由后台真实判定 |

## 4.2 功能详情

### 4.2.1 入口与浮窗

- **入口位置**：开启采购弹窗 → “合作品类”字段行 → 下拉框右侧“智能推荐”文字按钮。
- **浮窗形态**：从页面右侧滑入的窄浮窗，覆盖在当前页面之上，宽度约 520～700 像素，占屏幕宽度约 38%；开启采购弹窗保持打开。
- **浮窗标题**：智能推荐合作品类；标题左侧为关闭按钮。
- **顶部提示**：浅黄色提示条，文案为“通过填写招采名称 系统智能推荐合适的合作品类”。
- **互斥规则**：与合作品类的“智能推荐”浮窗同一时间只能打开一个；打开采购品类的智能推荐浮窗时，本浮窗关闭。

### 4.2.2 招采名称录入与校验

- 招采名称为必填项，输入框占满浮窗内容宽度，最多输入 100 字。
- 占位提示为“请输入招采名称”。
- 输入框下方展示示例：“示例：XX项目2026年度商品混凝土及砂浆集中采购”，右侧提供“填入示例”文字按钮。
- “填入示例”只替换输入内容，不自动发起推荐。
- 点击“立即推荐”或在输入框内按回车键时校验：
  - 空内容或纯空格：在浮窗内提示“请先输入招采名称”，不发起推荐，不展示结果。
  - 输入有效：清除错误提示，进入推荐流程。
- 输入内容发生变化时：清除当前错误提示，并清除上一次推荐结果。

### 4.2.3 智能推荐规则

- **推荐依据**：招采名称文本与合作品类关键词库的包含关系。
- **本期关键词库示例**（原型内置，正式实现由后台词库提供）：

| 合作品类 | 关键词示例 |
|----------|------------|
| 钢材及金属制品 | 钢筋、钢材、钢板、型钢、钢管、螺纹、钢结构、金属、铁件、止水钢板 |
| 模板脚手架及周材 | 模板、木方、脚手架、周材、盘扣、铝模、木模、支撑架、安全网 |
| 机电设备 | 电缆、电线、配电、桥架、母线、机电、电梯、空调、水泵、风机、变压器、设备 |
| 装饰装修材料 | 装修、装饰、涂料、瓷砖、石材、门窗、吊顶、乳胶漆、地板、幕墙 |
| 混凝土及砂浆 | 混凝土、砂浆、砼、搅拌站、湿拌、干混、外加剂 |

- **唯一结果规则**：若命中多个合作品类，按“命中关键词的字符长度合计”比较，合计最大的品类作为推荐结果；长度相同时保留词库中靠前的品类。
- **命中依据展示**：从命中关键词中按出现顺序取最多 3 个，以“招采名称包含关键词「A」「B」「C」”的形式展示。
- **无命中**：进入未匹配形态，不给出默认品类、不做猜测性推荐。
- **推荐时延**：原型使用约 0.9 秒的模拟等待；正式实现以接口返回为准，等待期间展示“推荐中…”。

### 4.2.4 推荐结果与采用

- 结果区位于推荐按钮下方，白底描边卡片。
- 匹配成功时展示：
  - 标签“推荐结果”；
  - 推荐的合作品类名称（加粗）；
  - 右侧“立即使用”主按钮；
  - 下方一行命中依据。
- **采用规则**：
  - 点击“立即使用”后，把推荐品类回填到开启采购弹窗的“合作品类”下拉框；
  - 若该字段此前有“请选择合作品类”的校验错误，一并清除；
  - 关闭推荐浮窗，开启采购弹窗保持打开；
  - “合作品类”字段出现约 1.6 秒的高亮提示；
  - 页面出现轻提示“已采用推荐合作品类：XXX”，约 2.8 秒后自动消失。
- **不自动采用**：展示推荐结果后，不点击“立即使用”不会修改表单。

### 4.2.5 未匹配引导

- 未匹配时展示：
  - 标签“推荐结果”；
  - 文案“未匹配到”；
  - 说明文案：“合作品类库中暂无与本次招采名称匹配的品类，可先前往合作品类库申请添加，审核通过后即可选用。”
- “前往合作品类库申请添加”为文字链接：
  - 正式实现：跳转到合作品类库的申请添加页面，申请与审核流程由该页面承接；
  - 原型阶段：以“前往「合作品类库」申请添加合作品类（示意跳转）”轻提示示意。
- 未匹配不阻断开启采购流程，经办人仍可手动选择合作品类。

### 4.2.6 关闭与状态保持

- **关闭按钮**：仅关闭推荐浮窗，不修改表单，不清空弹窗内容。
- **Esc 键**：存在推荐浮窗时先关闭浮窗；不存在浮窗时才关闭开启采购弹窗。
- **点击弹窗遮罩**：存在推荐浮窗时只关闭浮窗；再次点击才关闭开启采购弹窗。
- **重新打开**：每次打开推荐浮窗均为全新状态，不保留上一次的输入和结果。
- **采用或关闭后**：开启采购弹窗内的其他字段值保持不变。

### 4.2.7 原型演示开关（仅原型）

- 推荐按钮左侧提供“演示：匹配到 / 未匹配到”分段开关，用于演示两种结果形态。
- 该开关仅用于原型评审和测试演示，正式实现不提供，命中与否由后台真实判定。
- 切换演示状态时清除当前推荐结果，需重新点击“立即推荐”。

##### 信息项说明

| 信息项 | 填写要求 | 展示说明 | 规则 |
|--------|----------|----------|------|
| 招采名称 | 必填，最多 100 字 | 单行输入框，占满内容宽度 | 空或纯空格不可推荐；内容变化后清除旧结果 |
| 示例名称 | 非填写项 | 输入框下方灰色示例文案，附“填入示例”链接 | 只填入名称，不自动推荐 |

##### 交互说明

- **打开**：点击“智能推荐”后浮窗从右侧滑入，开启采购弹窗及已填内容保持不动。
- **推荐中**：按钮文案变为“推荐中…”，按钮禁用；此期间按回车不重复触发。
- **校验失败**：在按钮下方显示红色提示“请先输入招采名称”，不展示结果区。
- **结果过期**：修改名称后旧结果立即消失，避免误采用。
- **采用结果**：点击“立即使用”后浮窗关闭，字段回填并高亮，出现成功轻提示。
- **未匹配**：只展示说明和补库入口，不提供“立即使用”。
- **关闭层级**：关闭按钮、Esc 键、点击遮罩均只关闭最上层浮窗，再次操作才关闭开启采购弹窗。
- **浮窗互斥**：与合作品类推荐、采购品类推荐浮窗同一时间只存在一个。

##### 异常处理

| 异常场景 | 页面表现 | 后续动作 |
|----------|----------|----------|
| 未输入招采名称 | 提示“请先输入招采名称” | 补充输入后重新推荐 |

- 浮窗打开动画时长 ≤ 0.3 秒，打开过程不出现明显卡顿。

- 推荐中状态反馈（按钮文案变化）在点击后 100 毫秒内出现。
- 回填与关闭浮窗在点击“立即使用”后 300 毫秒内完成。
- 轻提示自动消失时间约 2.8 秒，字段高亮约 1.6 秒。

# 7. 非功能性需求

## 7.1 性能需求

- 推荐服务在常规并发下保持稳定，单次推荐目标 90% 请求 ≤ 1.5 秒。
- 浮窗打开、关闭、回填等前端交互无明显延迟。
- 推荐失败或超时不超过 5 秒仍无响应时，必须给出失败提示，不能一直停留在“推荐中…”。

## 7.2 可用性需求

- 推荐服务不可用时，不影响开启采购弹窗的正常填写和提交；合作品类仍可手动选择。
- 浮窗关闭、弹窗关闭、页面刷新等操作不产生脏数据。
- 同一用户重复操作不会产生重复回填或重复提交。

## 7.3 安全需求

- 招采名称仅用于本次推荐，不对外展示、不用于与推荐无关的用途。
- 推荐日志需脱敏，不记录与业务无关的个人信息。
- 未匹配引导跳转需校验登录态和权限，无权限用户不能进入合作品类库申请页面。

## 7.4 数据统计需求

需要统计：推荐触发、推荐成功、未匹配、立即使用、重新推荐、前往申请添加、关闭方式（关闭按钮 / Esc 键 / 遮罩 / 采用后自动关闭）。统计维度包括：组织机构、采购经办人、日期、招采名称关键词、推荐品类、是否采用。

## 8.2 本期不包含

- 合作品类库申请添加的表单与审核流程。
- 推荐关键词库的后台配置与维护界面。
- 推荐模型训练、语义理解、多候选排序。
- 历史推荐记录、推荐结果反馈（有用/无用）。
- 合作品类与采购品类的联动推荐。

## 8.3 后续可规划

- 多候选推荐及置信度展示。
- 根据已选采购品类反向校验合作品类。
- 推荐结果“有用/无用”反馈，用于优化词库。
- 关键词库后台维护与命中效果看板。
- 推荐后自动带出采购品类候选。
