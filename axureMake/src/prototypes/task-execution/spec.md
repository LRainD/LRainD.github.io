# 检查任务详情页面规格文档

## 1. 页面概述

检查任务详情承载单次自查、互查、稽查任务的检查执行、整改、复核和历史记录查看。该原型内容已合并至“我的任务”页面，由其操作列切换至当前页面内的办理视图，并由 `taskId` 与 `mode` 状态恢复当前任务及办理模式。

## 2. 页面结构

- 顶部：面包屑下方复用顶部操作栏组件，左侧展示返回任务列表、页面标题、任务编号和当前状态；可办理任务在右侧提供保存草稿和对应的提交按钮。
- 任务信息：检查类型、采购项目、合同信息和当前办理事项。
- 检查项处置明细：首轮自查不展示整改轮次和处置说明；展示检查项、检查标准、必填判定结果、自查备注及自查附件。整改和复核均以检查项为单位，按整改轮次在表格内依次展示“第 N 轮整改说明、整改材料、第 N 轮复核判定结果、复核意见”。
- 办理区：自查时逐项选择判定结果，并填写自查备注、上传自查附件；整改时仅在需整改的检查项行填写新一轮整改说明和材料，最近一轮复核通过的检查项不再展示下一轮输入控件；复核时保留原始判定及全部历史整改数据，并在每个待复核检查项的最新轮次填写新的复核判定结果和复核意见。复核不通过后，该检查项新增下一轮整改列。
- 任务流转记录：展示任务派发、检查提交和当前待办等关键业务事件。

## 3. 交互规则

- “检查”用于自查、互查、稽查待处理或进行中任务；自查任务的表格字段固定使用“判定结果”“自查备注”“自查附件”，可保存草稿并提交检查。
- “整改”用于待处置或复核不通过任务，合同经办人按检查项填写本轮整改说明、上传本轮材料后提交，生成原检查人的复核待办。
- “复核”用于待复核任务，原检查人可查看原始判定和历轮整改记录，并在最新整改轮次逐项给出通过或不通过结论；不通过的检查项进入下一轮整改。
- “查看”以只读方式展示任务明细与流转记录。

## 4. 视觉规范

- 复用集采工作台布局和 Ant Design 卡片、表格、描述列表、时间轴组件。
- 页面背景使用浅灰，信息模块采用白色卡片；风险和待处置提示使用黄色，状态标签按任务状态展示。
