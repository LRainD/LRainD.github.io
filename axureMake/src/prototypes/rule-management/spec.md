# 规则管理

规则管理页面本次为功能迭代。页面共两个：规则列表页、规则新增 / 详情页。

## 📋 核心目标

本次迭代的核心目标：

- 新增“人工检查”类型的规则，支持配置人工检查的规则，并返回给“一单一检”使用。
- 提供系统规则计算能力。

## 🆕 本次新增字段

以下字段为本次规则管理页面新增字段：

| 字段 | 所在位置 | 类型 | 说明 |
|---|---|---|---|
| **检查类型** | 新增页基本信息、列表筛选、列表展示 | 下拉选择 | 可选“系统识别”或“人工检查”，用于控制新增页的配置项联动。 |
| **检查标准** | 人工检查专用配置、列表展示 | 文本输入 / 文本展示 | 仅在“检查类型”为“人工检查”时填写和展示，用于填写人工检查标准。 |
| **检查阶段** | 人工检查专用配置 | 级联下拉（必填） | 仅在“检查类型”为“人工检查”时显示，用于选择检查所属阶段；当前阶段选项暂由阿波罗配置，便于后续快速调整。 |

其中，“检查类型”新增到列表页的筛选条件与展示列；“检查标准”新增为列表展示列；“检查标准”和“检查阶段”用于新增规则时的人工检查配置。

---

## 页面一：规则列表页

### 要做什么事

规则列表查看：浏览规则信息，支持查询过滤。

### 页面内容

- **筛选条件**：规则名称、规则编号、检查类型、业务域、业务类型、操作人、操作时间、规则等级、规则类型、状态。
- **列表字段**：序号、规则编号、规则名称、业务域、业务类型、检查类型、检查标准、状态、规则等级、规则类型、操作人信息、操作时间、备注。
- **本次新增**：在规则列表中显示“检查类型”，并提供对应的筛选功能；“检查标准”新增为列表展示列。

---

## 页面二：规则新增 / 详情页

### 要做什么事

新增规则：支持设置“检查类型”，并联动显示对应配置项，完成业务域、业务类型、规则名称、规则编号等配置项管理。

### 表单结构

1. **检查类型**：下拉选择（系统识别/人工检查，必填）
2. **业务域/业务类型**：下拉选择
3. **规则名称/规则编号**：输入框
4. **人工检查专用配置**（选择“人工检查”时显示）：
   <!-- - 检查标准（文本输入） -->
   - 检查阶段（级联下拉，必填；阶段选项暂由阿波罗配置，便于后续快速调整）
5. **系统识别专用配置**（选择“系统识别”时显示）：
   - 安全规则、处置建议、规则等级、规则类型、是否大模型

### 交互逻辑

- **检查类型联动**：
  - **系统识别**：显示规则字段模块及系统识别专用配置项。
  - **人工检查**：隐藏“规则字段”模块，显示人工检查专用配置项（检查标准、检查阶段）。
- **检查阶段配置**：人工检查必须选择检查阶段；阶段选项暂由阿波罗配置，以便后续快速调整。

### 检查阶段选项

检查阶段为两级级联结构，当前选项如下（暂由阿波罗配置）：

| 一级（阶段大类） | 二级（具体阶段） |
|---|---|
| 招标/采购阶段 | 采购申请阶段 |
| 招标/采购阶段 | 约标/发起阶段 |
| 招标/采购阶段 | 发标/响应阶段 |
| 招标/采购阶段 | 开标/开启阶段 |
| 招标/采购阶段 | 评标/评审阶段 |
| 招标/采购阶段 | 定标/成交阶段 |
| 合同阶段 | 合同签署 |

## 🔌 对外接口规划

> 以下接口为产品层面的能力定义，具体请求方式、参数格式、鉴权方式、错误码及分页策略由研发结合系统架构确定。

### 规则查询接口

**接口目标**：根据外部传入的组织、检查类型和检查阶段，查询该场景下对应的检查项列表。

**白名单与规则授权**：

- 本接口仅返回调用方被授权的规则和检查项，需由研发实现白名单控制；不在白名单内的调用方不可查询。
- 授权范围基于运营管理的配置：只有在运营管理已配置授权的规则，才允许被查询和返回。
- 在此基础上，还需支持按“一单一检”场景配置可使用的规则，即运营管理可指定某组织/场景在“一单一检”下允许使用的规则集合。
- 当前“一单一检”的定义：**大模型规则、工商关联规则不能使用**，其余规则可按运营管理的授权配置放行。该排除范围后续可由运营管理调整。

**请求参数**：

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| 组织 | string / object | 是 | 外部传入的组织标识或组织信息，作为规则匹配的业务上下文。 |
| 检查类型 | string | 是 | `system`：系统识别；`manual`：人工检查。 |
| 检查阶段 | string / array | 是 | 检查所属阶段。人工检查根据该参数匹配“检查阶段”配置；系统识别可按研发实现决定是否使用该参数过滤。 |

**返回内容**：

- 对应的检查项列表。
- 每个检查项至少包含检查项标识、检查项名称、检查类型及检查标准等信息。
- **人工检查**：根据传入的检查阶段，匹配规则配置中对应的检查阶段；仅返回符合条件的检查项，并返回该检查项配置的检查标准。
- **系统识别**：暂时不根据传入组织过滤，默认返回无计算成本的系统检查项，并返回检查标准字段；有计算成本的规则暂不返回，当前需要排除的规则包括“大模型规则”和“工商关联”规则。具体可计算字段及参数结构由研发定义。
- 未匹配到检查项时，返回空列表，并按研发约定返回状态或提示信息。

### 规则计算接口

**接口目标**：对外提供系统识别检查项的计算能力，返回检查结果及对应的业务说明。

**请求参数**：

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| 系统检查项 | array / object | 是 | 规则查询接口返回的、需要执行计算的系统检查项及其计算所需数据。 |
| 业务数据 | object | 是 | 执行检查计算所需的业务上下文和业务字段，具体字段由研发根据检查项定义。 |

**返回内容**：

- 检查结果：`通过` 或 `不通过`。
- 当检查结果为 **不通过** 时，返回风险预警信息，包括风险描述、风险等级、风险项标识等内容；具体字段由研发定义。
- 当检查结果为 **通过** 时，返回当前数据描述，用于说明本次检查使用的数据及当前状态；具体字段由研发定义。
- 支持一次请求计算一个或多个系统检查项，批量返回每个检查项对应的检查结果；批量能力及异常项处理方式由研发确定。

### 接口约束与待研发确认项

- 规则查询接口只返回调用方有权限访问的规则和检查项。
- 规则计算接口仅面向系统识别检查项开放，人工检查项不通过该接口执行计算。
- 具体接口路径、HTTP 方法、请求及响应 JSON 结构、字段命名、错误码、超时重试、幂等策略和版本管理方式由研发确定。
