# 规格说明｜标后巡检宣传页

- 页面目录：`src/prototypes/post-award-inspection/`
- 页面类型：产品宣传页（营销型单页，非后台业务页）
- 主题：`antd-new`（品牌蓝 #1F6BFF，深海军蓝 #08172B，履约青 #0FB5A6，疑点琥珀 #F59300）
- 状态：v0.1 初稿，待业务方确认叙事与范围

## 1. 一句话定位

数字合规官是**事中**（招标过程中实时校验程序合规），标后巡检是**事后**（中标之后回溯核查履约合规）；本页负责把「为什么需要事后这一段」讲清楚，并让人相信这件事做得成。

## 2. 目标受众

| 受众 | 关心什么 | 页面要给出的答案 |
| --- | --- | --- |
| 集采 / 采购管理层 | 钱花出去之后有没有人管 | 中标后 6 类高风险场景都能被巡到 |
| 合规 / 风控人员 | 凭什么说我查得准、查得完 | 承诺基线 + 证据链 + 分级定级 |
| 业务专家 / 项目经理 | 会不会增加我的工作量 | 四步流程，只做判断与处置 |
| 供应商管理岗 | 结果能不能用起来 | 履约结论回写信用档案、反哺准入评标 |

## 3. 页面结构（自上而下）

| 区块 | 目的 | 关键内容 |
| --- | --- | --- |
| 顶部导航 | 定身份、给出口 | 品牌「标后巡检 · 履约合规」+ 5 个锚点 + 看样本 / 预约演示 |
| Hero | 建立立场与画面感 | 主张「招标结束，合规才走到最难的一段」；右侧巡检任务卡（96/128 项、3 条疑点可点开） |
| 两个哨位 | 与数字合规官划清分工 | 四段轨道（策划 → 招标 → 合同履约 → 信用沉淀）+ 事中 / 事后双卡 |
| 巡什么 | 把风险具体化 | 6 张场景卡：合同一致性、转分包、人员到岗、材料降配、变更签证、结算支付，每张带「典型疑点」 |
| 怎么巡 | 证明可执行 | 四步：数据接入 → 规则+AI → 定级与证据链 → 派单归档；附规则 / 语义 / 人工三引擎说明 |
| 能力底座 | 说明为什么比人工强 | 承诺基线、证据链、横向画像、信用沉淀 |
| 效果量级 | 给决策者一个尺度 | 4 项示意数据（明确标注为演示示意） |
| 落地方式 | 降低启动心理成本 | 选 1 个项目 3 步跑通 + 试点范围建议 + 行动按钮 |
| 页脚 | 免责与串联 | 关联数字合规官、声明演示示意数据 |

## 4. 核心交互

1. **锚点导航**：滚动到区块时导航项高亮（IntersectionObserver）；滚动超过 24px 后导航由透明转白底（document 捕获阶段滚动监听，兼容 body / window 两种滚动容器）。
2. **疑点样本弹层**：Hero 三条疑点、巡检范围区的「材料降配样本」入口均可打开弹层，内容含结论、3 条证据（原文出处 + 事实）、处置建议、关联疑点。支持 ESC / 点击遮罩关闭，打开时锁定背景滚动；点「派单核实」关闭弹层并弹出轻提示（演示口径）。
3. **滚动入场**：区块 `[data-reveal]` 淡入上移，只播放一次；`prefers-reduced-motion` 下不启用。
4. **卡片反馈**：场景卡 hover 上浮 + 顶部渐变线；疑点行 hover 右移。

## 5. 内容口径

- 不承诺「自动判定违规」：模型只给疑点与证据，结论与处置由人签字确认。
- 不贬低数字合规官：明确「接力关系」，共用规则库、证据链、整改台账。
- 所有数字（2 小时、82%、1.2 亿等）标注为演示示意数据，避免被当作已交付指标。
- 术语与现有原型一致：合同额、变更签证、专业分包、履约档案、整改台账。

## 6. 技术实现

- `index.tsx` 单文件页面 + 内部子组件（Nav / Hero / Why / What / How / Ability / Stats / Launch / Footer / SampleDialog）。
- 视觉全部用 CSS + 内联 SVG 绘制，不引用外部图片，保证导出为单 HTML 时无资源 404。
- 仅使用 antd `Button`（其余为原生按钮与自绘结构），避免 antd v6 API 漂移；弹层自绘以完全控制样式与键盘行为。
- 数据集中在文件顶部常量（heroIssues / inspectItems / steps / capabilities / stats / samples），改文案不需要动结构。
