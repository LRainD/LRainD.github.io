# 预警核查列表新增列迭代 PRD

## 1. 迭代目标
在运营后台「风控预警中心 > 预警核查」列表中补充用于判定与组织归属的信息列：新增「初始判定数据」列，以及「所属局级组织」「所属局二级组织」两列，帮助运营人员快速还原预警判定依据并定位责任单位；同时新增「解除人」「解除说明」两列，便于在人工解除场景下排查解除操作人及解除原因。

## 2. 迭代范围
本次迭代仅涉及列表列的新增，页面菜单、查询区、其他列及已有弹窗、抽屉交互均保持不变。

## 3. 列表新增列

### 3.1 初始判定数据
- 位置：在「预警类型」列右侧、「当前数据」列左侧新增「初始判定数据」列。
- 内容：展示该条预警在首次判定时使用的核心业务数据，用于与「当前数据」对照查看数据变化。
- 展示规则：单元格内容超出列宽时省略展示，悬浮显示完整内容。
- 数据示例：
  - 不合格附件：3份
  - 有效投标供应商：2家
  - 合同金额：1,286万元
  - 报价时长：18小时

### 3.2 所属局级组织
- 位置：在「组织机构」列右侧新增「所属局级组织」列。
- 内容：展示该条预警所属的局级单位。
- 数据示例：中建一局、中建二局、中建科工。
- 展示规则：单元格内容超出列宽时省略展示，悬浮显示完整内容。

### 3.3 所属局二级组织
- 位置：在「所属局级组织」列右侧新增「所属局二级组织」列。
- 内容：展示该条预警所属的局二级单位，与「所属局级组织」为上下级对应关系。
- 数据示例：建设发展公司、二局华东公司、二局三公司、二局华西公司、科工湖北公司。
- 展示规则：单元格内容超出列宽时省略展示，悬浮显示完整内容。

### 3.4 解除人
- 位置：在「预警解除状态」列右侧新增「解除人」列。
- 内容：展示执行人工解除的操作人，格式为「姓名（账号）」，便于排查该预警由谁解除。
- 展示规则：未解除的数据显示「-」；内容超出列宽时省略展示，悬浮显示完整内容。
- 数据示例：李伟（liwei03）、周婷（zhouting02）。

### 3.5 解除说明
- 位置：在「解除人」列右侧新增「解除说明」列。
- 内容：已填写解除说明的数据展示「查看说明」按钮，点击后弹窗展示解除人、业务编号、预警规则及完整解除说明；无说明的数据显示「-」。
- 弹窗标题为「解除说明」，底部提供「关闭」按钮。
- 数据示例：人工解除：经核实合同金额已包含变更签证部分，未超出招标预算上限，判定为误报，予以解除。

## 4. 列顺序
新增后列表列顺序为：序号、业务域、业务编号、业务名称、业务类型、组织机构、所属局级组织、所属局二级组织、经办人、业务环节、预警规则、预警级别、检测场景、预警类型、初始判定数据、当前数据、预警解除状态、解除人、解除说明、审查依据、预警时间、是否满意、反馈次数、tid、操作。

## 5. 验收标准
1. 列表在「预警类型」列右侧、「当前数据」列左侧展示「初始判定数据」，内容与数据源一致。
2. 列表在「组织机构」列右侧依次展示「所属局级组织」和「所属局二级组织」，且二级组织与局级组织归属对应。
3. 上述三列内容超出列宽时省略展示，鼠标悬浮可查看完整内容。
4. 列表在「预警解除状态」列右侧依次展示「解除人」「解除说明」两列，已解除数据可看到解除人。
5. 点击「解除说明」列的「查看说明」后弹窗展示完整解除说明，关闭后回到列表。
6. 通过「解除风险」操作解除的数据，解除人默认记录为当前操作人，并生成对应的解除说明。
7. 新增列不影响原有列的展示顺序、固定列（序号、操作）及已有筛选、弹窗、抽屉交互。
