# AI物料标准化与价格治理平台 产品需求文档（PRD）

> **文档版本**：v1.0 **创建日期**：2026-10-22 **文档状态**：初稿 **产品定位**：建筑行业企业级SaaS，基于AI大模型的物料主数据标准化与价格数据治理平台

---

## 一、产品概述

### 1.1 行业痛点

建筑行业物料数据长期处于"三无"状态：

| 痛点类型 | 具体表现 | 业务影响 |
| --- | --- | --- |
| **名称非标** | 同一物料有N种叫法（如"HRB400E热轧带肋钢筋"可能被写为"三级钢"、"抗震钢筋"、"E标螺纹钢"等） | 跨项目、跨组织的价格对比无从谈起 |
| **规格不统一** | 规格维度缺失或混乱（灯泡有的写"220V 100W"，有的只写"大瓦数灯"） | 物料无法精准匹配，价格无法横向参考 |
| **价格数据散** | 价格分散在合同、招标清单、结算单等系统中，非结构化存储 | 历史价格无法复用，询价只能逐项目翻合同 |
| **治理效率低** | 传统线下专家标注物料，1亿条量级数据无法逐条处理 | 主数据治理永远在半途，迟迟无法闭环 |

### 1.2 产品定位

面向中建体系（各工程局）等大型建筑集团，提供一套"**AI原子化拆解 → 人机协同组装 → 标准库建立 → 价格关联入库 → 业务场景应用**"的闭环链路，让标准化治理从"专家人肉标注"升级为"AI加速 + 人机协同"，让价格数据从"沉睡在合同里"变为"随时可查的参考资产"。

### 1.3 核心价值主张

*   **对治理团队**：将物料标准化效率提升10倍以上（AI完成80%初筛，专家做20%确认）
    
*   **对商务/招采**：投标询价时，3秒内拿到同品类、同规格、同区域的历史签约参考价
    
*   **对管理层**：跨工程局的物料价格横向可比，支撑集采决策与成本管控

## 二、目标用户与角色

### 2.1 用户角色矩阵

| 角色 | 所属部门 | 核心诉求 | 使用场景 |
| --- | --- | --- | --- |
| **治理管理员** | 信息化/供应链管理部 | 全局推进治理进度 | 配置数据源、分派任务、监控进度、管理标准库 |
| **业务专家** | 各工程局物资部/成本部 | 高效完成物料标准化 | 审核AI抽取的原子词条、组装标准物料、确认价格入库 |
| **商务人员** | 投标中心/经营部 | 投标时精准报价 | 上传清单→自动匹配标准物料→获取参考价差 |
| **招采人员** | 采购中心 | 询价时有据可依 | 非标清单上传→匹配相似项目签约价→多维度筛选 |
| **装饰工程师** | 装饰/精装部门 | 快速估算装饰成本 | 清单描述输入→匹配相似项目→查看价格区间 |

### 2.2 典型用户画像

**业务专家（核心用户）**

*   张工，中建某工程局物资部主任工程师，从业15年
    
*   每天需要审核数百条物料标准化申请，以往靠Excel人工逐条核对
    
*   期望：AI先拆好原子词条，我只需要打勾确认，1天能完成以前1周的活
    

**招采人员（高频用户）**

*   李姐，采购中心主管，负责大宗材料询价
    
*   每次询价都要翻近5年合同，找同规格钢筋的签约价
    
*   期望：上传招标清单，AI直接给我同区域、同时间的参考价，还能选工程局范围

## 五、功能模块详细说明

### 5.1 一期：基础治理（MVP）

#### 5.1.1 数据源接入

**功能描述**：支持多渠道物料数据的批量导入与预处理。

| 数据源类型 | 输入形式 | 处理方式 |
| --- | --- | --- |
| 采购Excel清单 | .xlsx/.xls | 自动识别列头→统一字段映射→去重清洗 |
| 合同文本 | .pdf/.docx | OCR + 大模型抽取物料条目 |
| 招标清单 | .xlsx/.pdf | 结构化解析→物料条目批量提取 |

**核心交互**：

*   拖拽上传区：支持多文件批量上传，单个文件≤100MB
    
*   字段映射向导：Excel列头与标准字段（物料名称、规格、单位、数量等）的拖拽映射
    
*   导入预览：展示解析后的前50条数据，用户确认后进入AI拆解队列
    

**验收标准**：

*   Excel清单解析准确率 ≥ 95%
    
*   合同PDF物料抽取召回率 ≥ 90%
    
*   单次批量导入支持 ≥ 50万条物料记录
    

---

#### 5.1.2 AI原子化拆解引擎

**功能描述**：基于大模型对物料文本做语义解析，自动抽取规格属性词条及枚举值，将非标物料描述拆解为"原子化"的属性维度。

**技术原理示例**：

| 原始物料描述 | AI原子化拆解结果 |
| --- | --- |
| "螺旋节能灯 22W E27暖光" | 品类：灯泡 |
|  | 属性原子：{品类:灯泡, 类型:螺旋节能灯, 功率:22W, 灯头口径:E27, 色温:暖光} |
| "HRB400E Φ25mm 热轧带肋抗震钢筋" | 品类：钢筋 |
|  | 属性原子：{品类:钢筋, 牌号:HRB400E, 直径:25mm, 外形:热轧带肋, 特性:抗震} |

**功能要点**：

*   大模型语义抽取：支持数千种建材品类的规格属性识别（可扩展品类词典）
    
*   枚举值规范化：将自由文本归一为标准枚举（如"暖光"/"暖白"/"3000K"→统一为"色温:暖光"）
    
*   置信度输出：每个原子词条附带AI置信度（高/中/低），低置信度词条标记为"需人工确认"
    
*   增量学习：专家的修正反馈回流模型，持续优化拆解准确率
    

**验收标准**：

*   原子词条抽取准确率 ≥ 85%
    
*   枚举值归一准确率 ≥ 80%
    
*   单条物料拆解响应时间 ≤ 3秒
    

---

#### 5.1.3 线上治理工作台

**功能描述**：为业务专家提供物料标准化的人机协同操作界面，是一期的核心交互载体。

##### 工作台子模块一：物料原子库浏览

*   以品类分组展示AI拆解后的原子词条集合
    
*   支持按品类、工程局、置信度、处理状态多维度筛选
    
*   每条物料卡片展示：原始描述、AI拆解结果（复选框形式）、当前状态（待处理/处理中/已完成）
    

##### 工作台子模块二：专家组装界面

**核心交互设计**：

*   左侧：AI抽取的原子词条（复选框形式，按属性维度分组）
    
*   中间：实时组装预览区，勾选原子后动态生成标准物料描述
    
*   右侧：相似标准物料推荐（基于已入库标准库的向量相似度匹配，辅助专家判断）
    
*   底部操作区：「确认入库」「标记为废弃」「拆分处理」三个核心按钮
    

> 交互模式参考AI绘画工具（如Midjourney）：AI先给出初筛结果，用户通过勾选/微调完成最终确认。

##### 工作台子模块三：任务分派与进度追踪

| 功能 | 说明 |
| --- | --- |
| 任务创建 | 管理员按品类+工程局创建治理任务，设置截止日期 |
| 任务分派 | 指定业务专家或专家组，支持一人多任务 |
| 进度看板 | 全局进度仪表盘：总任务数、已完成、逾期、按品类/工程局分布 |
| 催办提醒 | 截止日期前3天自动提醒，逾期标红并推送通知 |

---

#### 5.1.4 标准物料库

**功能描述**：已确认的标准物料词条库，是整个平台的知识基座。

**数据结构要点**：

```plaintext
标准物料 = {
  标准ID,
  标准名称,           // 规范化后的统一名称
  品类分类,           // 品类树节点（如 建材→钢材→钢筋）
  属性原子集合,       // [{属性维度, 属性值}]
  同义词列表,         // 历史非标叫法（用于匹配召回）
  创建时间,
  最后确认专家,
  关联价格条目数
}

```

**功能要点**：

*   全文搜索：支持按名称、属性、同义词模糊搜索
    
*   浏览模式：品类树导航 + 卡片列表双模式
    
*   映射管理：展示某标准物料覆盖了多少历史非标叫法
    
*   版本管理：标准物料支持迭代（如新增属性维度），保留历史版本

### 5.2 二期：价格治理与应用

#### 5.2.1 价格数据清洗

**功能描述**：从合同文本、招标清单中自动抓取价格数据（不包含结算单，结算单价格权威性最低）。

**数据来源优先级（关键决策）**：

```plaintext
合同文本 > 招标清单 > 结算单（最低，暂不纳入）

```

**清洗规则**：

*   按"同物料+同时间窗口"聚合多条价格，保留最权威来源
    
*   识别异常值（如单价为0、远高于/低于同品类均价3σ），标记为待人工确认
    
*   统一货币单位、数量单位
    

---

#### 5.2.2 价格入库审核

**功能描述**：业务专家对AI自动匹配到标准物料的价格做最终确认。

**交互设计**：

*   AI自动完成：价格记录 ↔ 标准物料 的匹配（置信度标注）
    
*   专家视角：看到的是"某标准物料"下挂着若干条候选价格记录
    
*   操作选项：「选用此价格」「不选用」「价格存疑待复核」
    
*   支持批量操作：同一标准物料下多条价格可批量标记
    

**数据维度**：每条价格记录包含

*   标准物料ID
    
*   单价、数量、总价
    
*   来源（合同/招标清单）、来源文档ID
    
*   签约时间、签约工程局
    
*   项目区域（省/市）
    

---

#### 5.2.3 品牌信息治理

**功能描述**：

**品牌数据源优先级**：合同文本 > 招标清单 > 结算单

*   一期品牌由AI从合同文本自动提取，随价格一起入库
    
*   二期支持UGC品牌维护：专家可新增/修正品牌名称、品牌与标准物料的关联
    
*   品牌库独立管理：支持品牌全称、简称、别名的归一
    

---

#### 5.2.4 浮动价机制

**功能描述**：针对钢筋、水泥、砂石等大宗材料，支持"当期价 ± 浮动系数"的参考价计算模式。

**设计要点**：

*   支持配置浮动系数模板：按品类预设浮动上下限（如钢筋 ± 5%）
    
*   当期价来源：可对接外部行情接口，或取近30天入库的最新签约价
    
*   投标/询价场景中展示的参考价，会标注"含±3%浮动"等提示
    

---

### 5.3 三期：业务场景应用

#### 5.3.1 商务投标报价

**功能描述**：商务人员上传投标清单（Excel或CAD图纸），系统自动解析并匹配标准物料库，输出参考价差。

**输入→输出**：

```plaintext
输入：投标Excel清单 / CAD图纸
  ↓
处理：OCR解析 → 大模型识别物料条目 → 匹配标准物料库
  ↓
输出：
  ✓ 已匹配项：展示标准名称 + 参考价区间 + 价差（vs 投标单价）
  ✓ 未匹配项：标记为"待治理"，一键提交至治理队列
  ✓ 汇总报表：整份清单的参考价 vs 投标价 对比分析

```

**CAD解析特殊说明**：三期支持基础的CAD图纸物料识别（如给排水管材、线缆规格），非MVP范围。

---

#### 5.3.2 招采询价智能匹配

**功能描述**：招采人员上传非标询价清单，AI匹配历史相似项目的真实签约价格。

**筛选维度**：

*   区域：省/市/经济带
    
*   时间：近N个月/季度/年度
    
*   品类：按品类树筛选
    
*   工程局：可选开放范围（跨局/本局）
    

**交互特点**：

*   同一规格物料匹配到多条历史价时，以散点图/箱线图展示价格分布
    
*   支持"只看中标价"过滤
    
*   支持一键导出询价参考单
    

---

#### 5.3.3 装饰清单穿透

**功能描述**：装饰工程师输入一段清单描述（如"精装修酒店客房吊顶轻钢龙骨石膏板"），AI匹配相似项目并展示真实签约价格区间。

**技术特点**：

*   向量相似度匹配：基于大模型Embedding计算清单描述与历史项目的语义相似度
    
*   结果展示：Top 5 相似项目卡片，每张卡片展示项目基本信息 + 该清单子项的价格区间 + 匹配度评分
    
*   支持点击进入项目详情（脱敏后的合同片段）
    

---

#### 5.3.4 价格敏感数据脱敏

**功能描述**：在所有业务应用场景中，对价格敏感信息做脱敏处理。

**脱敏规则**：

*   默认不展示具体合同条款、不展示精确到个位的单价（保留两位小数或取整）
    
*   展示维度协商开放：各工程局可自主配置"对其他局开放哪些价格维度"
    
*   支持细粒度权限：某工程局仅可查看其他局的"区域+品类"级别参考价，不可定位到具体项目

## 六、数据模型要点

### 6.1 核心实体关系

```plaintext
标准物料库 ──1:N──→ 原子属性集合
     │
     ├──1:N──→ 历史价格记录
     │              │
     │              └──N:1──→ 合同/招标清单（数据源）
     │
     └──1:N──→ 同义词（非标叫法）

品牌库 ──1:N──→ 标准物料关联

任务 ──1:N──→ 物料条目（待治理）
  │
  └──N:1──→ 专家（处理人）

```

### 6.2 关键数据表结构（简化）

**标准物料表**：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| std\_id | VARCHAR(32) | 标准物料唯一ID |
| std\_name | VARCHAR(200) | 标准名称 |
| category\_path | VARCHAR(200) | 品类路径（如 建材/钢材/钢筋） |
| atoms | JSON | 属性原子集合 |
| synonyms | JSON | 同义词列表 |
| status | ENUM | 待审核/已生效/已废弃 |

**价格记录表**：

### 7.2 交互模式核心原则

1.  **AI先做80%，人确认20%**：所有页面先展示AI初筛结果，用户操作以勾选/微调为主
    
2.  **批量优先**：专家可按品类批量审核，避免逐条处理
    
3.  **相似推荐辅助决策**：右侧始终展示已存在的相似标准物料，避免重复创建
    
4.  **实时反馈**：每次专家操作都回流模型，下次AI拆解更精准

## 八、非功能需求

### 8.1 数据安全

| 需求 | 方案 |
| --- | --- |
| 敏感信息脱敏 | 价格展示脱敏、合同原文不对外暴露、仅输出参考价 |
| 工程局数据隔离 | 各工程局数据物理隔离或逻辑租户隔离，跨局数据访问需显式授权 |
| 传输加密 | HTTPS + 敏感字段AES加密存储 |
| 操作权限 | RBAC角色权限控制，支持到"某专家只能处理某工程局某品类"的细粒度 |

### 8.2 可审计性

*   所有专家确认操作留痕：操作人、时间、操作内容、之前值→之后值
    
*   支持溯源：任一标准物料或价格记录，可追溯其完整治理链路（原始数据→AI拆解→专家操作→入库）
    
*   审计日志保留期 ≥ 3年
    

### 8.3 AI准确性保障

*   人工反馈闭环：专家每次修正都会形成训练样本，按月迭代模型
    
*   置信度分级展示：高置信度自动过审、中置信度专家快速勾选、低置信度重点处理
    
*   准确率仪表盘：展示各品类AI拆解准确率、价格匹配准确率，支持按工程局查看
    

### 8.4 性能要求

| 指标 | 目标值 |
| --- | --- |
| 原子化拆解响应时间 | 单条 ≤ 3秒，批量1万条 ≤ 10分钟 |
| 标准物料库搜索响应 | ≤ 500ms |
| 投标清单解析 | 1000条物料 ≤ 2分钟 |
| 并发用户 | 一期 ≥ 100人同时在线 |

### 8.5 可扩展性

*   品类词典可配置：管理员可自行新增品类与属性维度
    
*   大模型可插拔：支持切换不同厂商大模型（兼容闭源API与开源模型）
    
*   数据源接口标准化：新增数据源类型只需实现统一解析接口
