# 局集采计划预测系统 PRD

## 1. 文档信息

| 项目 | 内容 |
|---|---|
| 产品名称 | 局集采计划预测系统 |
| 文档版本 | V1.0 |
| 文档状态 | 待评审 |
| 目标用户 | 局级采购计划编制人员、区域采购人员、审核人员、系统管理员 |
| 预测对象 | 指定年度局级集采计划 |

## 2. 背景与目标

### 2.1 业务背景

局级采购计划编制需要综合在建项目、合作品类、采购品类、采购方式、采购内容、区域和历史招采数据。现有人工方式存在历史数据利用不足、新接项目容易遗漏、局级计划与股份区域联采中心计划重复、概算金额和时间依据不透明等问题。

### 2.2 产品目标

系统每年根据指定的预测年度，识别有效在建项目和新接项目的潜在采购需求，参考上一年度及历史首年局级、本部、下级区域联采类型招采数据，排除股份区域联采中心的集采计划，自动生成可审核、可追溯、可调整的年度局级集采计划。

### 2.3 建设原则

1. 规则计算是必选主链路，大模型是可插拔的解释和增强能力。
2. 所有预测结果必须能追溯到项目、历史样本、规则版本和模型调用记录。
3. 系统预测值与人工调整值分离保存，不覆盖原始预测结果。
4. 预测失败或大模型不可用时，仍可基于规则生成计划。
5. 真实密钥不进入代码、PRD、日志、浏览器和接口响应。

## 3. 范围定义

### 3.1 本期范围

- 基础数据维护和批量导入
- 在建项目管理
- 历史招采数据导入、校验和标准化
- 股份区域联采中心排除规则配置
- 年度集采计划预测
- 概算金额、计划开始时间和完成时间预测
- 计划条目合并、拆分、去重和人工调整
- 审核发布、版本管理、导出和执行结果回填
- 可配置的大模型中转站、模型 ID 和密钥引用
- 操作审计、预测证据和模型调用审计

### 3.2 暂不纳入

- 供应商寻源、询价、合同签署和订单执行
- 复杂工程量清单自动识别
- 自动替代采购审批系统
- 以大模型直接决定最终采购计划

## 4. 角色与权限

| 角色 | 主要权限 |
|---|---|
| 计划编制员 | 查看数据、导入数据、创建预测任务、调整草稿、提交审核 |
| 审核员 | 查看预测依据、审核计划、退回修改、发布计划 |
| 区域用户 | 查看授权区域数据、补充项目和需求、提交区域建议 |
| 管理员 | 用户权限、字典、排除规则、预测参数、模型配置、审计查询 |
| 只读用户 | 查看和导出已授权的计划及报表 |

权限需要同时支持角色权限和数据范围权限。区域用户只能访问授权区域，管理员可配置组织和区域授权。

## 5. 核心业务口径

1. 预测年度为自然年度，计划窗口为该年度1月1日至12月31日。
2. 有效项目包括预测年度仍在建、已开工或已确定启动且存在采购需求的项目；已完工、取消、长期暂停项目不纳入。
3. 新接项目是指在数据截止日之后新增或首次纳入本系统、且预计在预测年度产生采购需求的项目。新接项目没有历史项目记录时，使用同类型、同区域、相近规模项目进行类比。
4. 历史首年招采是项目首次采购年度发生的招采记录。默认使用历史三年数据，管理员可以调整样本窗口。
5. 局级计划只纳入局级、本部和下级区域联采范围；股份区域联采中心范围的记录不生成局级计划。
6. 同一预测年度、区域、合作品类、采购品类、采购方式和采购内容的需求，在满足合并规则时生成一个计划条目；跨区域原则上拆分。
7. 一份年度计划包含多个明细条目；计划主表和明细表独立编号。

## 6. 产品流程

`维护基础数据 → 导入在建项目 → 导入历史招采数据 → 配置排除规则 → 运行预测 → 校验候选需求 → 合并/拆分/去重 → 人工审核 → 发布年度计划 → 执行跟踪 → 回填实际结果`

预测任务生成后采用草稿状态，不直接发布。审核员需要能查看每个条目的纳入原因、排除原因、历史样本、金额算法、时间算法和调整记录。

## 7. 功能需求

### 7.1 工作台

- 展示当前预测年度、数据截止日、最近任务状态和待办数量。
- 展示计划条目数、总概算金额、涉及项目数、覆盖区域数、待审核条目数。
- 展示高风险提示：基础数据缺失、未匹配品类、金额样本不足、可能重复、排除规则冲突。
- 支持按年度、区域、计划状态和任务状态筛选。

### 7.2 基础数据

维护并支持 Excel/CSV 导入、模板下载、字段校验、错误下载、停用和变更记录：

- 在建项目：项目编号、名称、区域、项目类型、项目状态、预计开工/完工时间、项目规模、合同额、是否新接项目。
- 合作品类：编码、名称、状态。
- 采购品类：编码、名称、所属合作品类、状态。
- 采购方式：编码、名称、适用范围、默认采购周期。
- 采购内容：编码、名称、所属采购品类、是否允许局级集采、默认周期。
- 区域：区域编码、名称、上级区域、层级、状态。

所有业务数据使用编码关联，名称仅用于展示。导入时禁止静默覆盖，必须显示新增、更新、无效和重复记录。

### 7.3 历史招采数据

- 支持批量导入和手工新增。
- 导入字段包括采购年度、项目编号、区域、联采类型、采购层级、合作品类、采购品类、采购方式、采购内容、实际金额、计划开始/完成时间、采购状态、组织单位。
- 自动校验项目、品类、方式、内容、区域编码是否存在。
- 自动识别项目某采购内容的首次采购年度，并允许管理员修正。
- 对名称相同但编码不同、同一项目重复记录、金额异常和日期倒置进行预警。

### 7.4 排除规则

规则字段包括规则名称、优先级、适用区域、合作品类、采购品类、采购方式、采购内容、联采类型、组织单位、有效起止日期、启用状态。

高优先级排除规则覆盖普通纳入规则。匹配到股份区域联采中心的候选需求必须标记为“已排除”，保留排除证据，不得直接删除。

### 7.5 年度预测任务

创建任务时填写：预测年度、数据截止日、历史样本年数、项目筛选范围、区域范围、是否启用大模型增强、金额估算参数、时间估算参数。

任务状态：待运行、运行中、规则完成、模型增强中、待审核、已完成、失败。任务支持取消、重跑和基于历史任务复制，但每次运行产生独立版本。

### 7.6 计划结果

年度计划主表字段：计划编号、年度、名称、状态、数据截止日、规则版本、预测任务编号、总条目数、总概算金额、创建人、审核人、发布时间。

计划明细字段：明细编号、计划编号、合作品类、采购品类、采购方式、采购内容、区域、概算金额、计划开始时间、计划完成时间、需求项目数、需求项目编号、联采类型、采购层级、预测评分、置信度、预测来源、纳入原因、调整状态、调整原因、执行状态。

支持列表、分组汇总、详情抽屉、批量编辑、拆分、合并、删除草稿条目、导出 Excel 和打印预览。已发布计划不可直接删除，只能通过变更版本修订。

### 7.7 审核与版本

流程为：草稿 → 待审核 → 退回 → 待发布 → 已发布 → 执行中 → 已完成。

审核必须填写结果和意见。发布前阻断以下问题：必填字段缺失、项目不存在、排除规则冲突、概算金额小于等于0、开始时间晚于完成时间、重复条目未处理。

每次预测、人工修改、审核、发布和回填均记录操作者、时间、前值、后值和原因。

### 7.8 执行回填

支持录入或导入实际采购金额、实际开始/完成时间、执行状态、未执行原因和偏差说明，生成预测金额偏差、时间偏差和项目覆盖率，为下一年度样本提供数据。

## 8. 预测算法设计

### 8.1 总体策略

采用“确定性规则 + 统计估算 + 可选大模型增强”的混合算法。规则负责范围、排除、去重和最终结构化结果；统计方法负责金额与时间；大模型只负责历史文本归一化、相似项目解释、候选建议和审核摘要。

### 8.2 规则步骤

1. 筛选预测年度有效项目并纳入新接项目。
2. 从历史数据识别同类项目首年采购内容、典型采购方式和联采类型。
3. 按项目类型、区域、项目规模、开工时间匹配历史样本。
4. 映射标准品类、方式、内容和区域编码。
5. 应用股份区域联采中心排除规则。
6. 对候选需求去重，并按可合并维度聚合。
7. 生成预测金额、时间、评分和证据。

### 8.3 概算金额

优先级为：同项目同内容历史值 → 同区域同类型项目中位数 → 全局同类型中位数 → 品类基准单价乘项目规模 → 人工填写。

金额估算需保存样本数、样本范围、统计方法、金额上下限和计算版本。样本少于可配置阈值时降低置信度并要求人工确认。异常值使用分位数截尾或中位数绝对偏差处理。

### 8.4 时间估算

`计划开始时间 = 项目预计开工时间 + 同类采购历史典型滞后天数`

`计划完成时间 = 计划开始时间 + 同类采购历史典型采购周期`

多项目合并时开始时间取最早需求时间，完成时间按最晚需求时间和集中采购周期计算；时间跨度超过配置阈值时自动建议拆分。

### 8.5 预测评分

评分综合历史出现频率、项目相似度、时间匹配度、局级适配度和数据完整度，输出0至100分及高/中/低置信度。评分只用于排序和审核提示，不得绕过排除规则。

## 9. 大模型能力与配置

### 9.1 使用场景

- 将历史采购内容名称归一化到标准采购内容。
- 从非结构化项目描述中抽取项目类型、规模和潜在采购关键词。
- 对规则筛选出的候选条目生成“为什么纳入/为什么排除”的自然语言解释。
- 对新接项目推荐相似历史项目和可能的首年采购内容。
- 对已生成计划进行重复、字段矛盾和异常描述检查。

大模型不得直接写入最终概算金额、日期或发布状态。模型输出必须经过 JSON Schema 校验、规则复核和人工审核。

### 9.2 配置项

后台提供模型配置页面，预留以下字段：

- 配置名称
- 中转站 Base URL，例如 `https://your-gateway.example.com/v1`
- 模型 ID，例如 `your-model-id`
- API 密钥：密码输入框，仅允许后端保存密文或密钥管理服务引用
- 请求超时、最大重试次数、温度、最大输出 Token
- 是否启用
- 适用功能：归一化、相似项目、解释、质量检查

页面只显示脱敏密钥，如 `sk-****abcd`，不能回显完整密钥。前端不保存密钥、不向浏览器下发密钥、不在日志中打印请求头、Prompt 中的项目敏感字段或完整响应。

### 9.3 调用约束

- 大模型调用只能由后端发起，使用 HTTPS。
- 中转站地址必须通过 URL 白名单校验，禁止任意内网地址和危险协议。
- 发送前进行数据脱敏和最小化，只发送完成当前任务所需的数据。
- 模型输出必须校验结构、枚举值、长度和引用 ID；校验失败则回退规则结果。
- 记录配置 ID、模型 ID、耗时、状态、Token 用量和脱敏摘要，不记录密钥。
- API 密钥通过环境变量或 Secret Manager 注入，生产环境禁止将真实密钥提交到仓库。

## 10. 数据库建议

建议表：`users`、`roles`、`regions`、`cooperation_categories`、`procurement_categories`、`procurement_methods`、`procurement_contents`、`projects`、`historical_procurements`、`exclusion_rules`、`forecast_tasks`、`forecast_candidates`、`annual_plans`、`annual_plan_items`、`plan_item_projects`、`plan_versions`、`adjustment_records`、`execution_records`、`model_configs`、`model_call_logs`、`audit_logs`。

所有核心表应包含主键、创建时间、更新时间、创建人、更新人、逻辑删除标记和数据版本字段。金额使用定点数，日期使用标准日期或时间戳，编码字段建立唯一索引。预测任务、计划和明细之间使用外键或等价引用保证可追溯。

## 11. 后端接口建议

接口统一使用 `/api/v1` 前缀，JSON 返回，统一错误码和请求 ID。主要接口如下：

| 方法 | 路径 | 用途 |
|---|---|---|
| GET/POST | `/projects` | 查询/新增项目 |
| POST | `/imports/projects` | 导入项目 |
| GET/POST | `/historical-procurements` | 查询/导入历史招采数据 |
| GET/POST | `/exclusion-rules` | 查询/配置排除规则 |
| POST | `/forecast-tasks` | 创建预测任务 |
| POST | `/forecast-tasks/{id}/run` | 运行预测 |
| GET | `/forecast-tasks/{id}/progress` | 查询进度和错误 |
| GET | `/forecast-tasks/{id}/candidates` | 查询候选结果及证据 |
| POST | `/annual-plans` | 从候选结果创建计划 |
| GET/PATCH | `/annual-plans/{id}` | 查询/编辑计划 |
| POST | `/annual-plans/{id}/submit` | 提交审核 |
| POST | `/annual-plans/{id}/review` | 审核或退回 |
| POST | `/annual-plans/{id}/publish` | 发布计划 |
| POST | `/annual-plans/{id}/export` | 导出计划 |
| GET/POST | `/model-configs` | 查询/保存模型配置 |
| POST | `/model-configs/{id}/test` | 后端测试模型连通性 |
| GET | `/audit-logs` | 查询审计日志 |

接口需要进行身份认证、权限校验、分页、过滤参数校验、上传文件类型和大小校验。批量导入和预测任务应异步执行。

## 12. 前端页面

1. 工作台：指标卡、任务状态、风险提示、待办。
2. 项目管理：筛选、详情、导入、校验结果、项目采购需求。
3. 基础字典：合作品类、采购品类、采购方式、采购内容、区域。
4. 历史招采：导入、首年识别、样本统计、异常处理。
5. 排除规则：规则列表、优先级、配置和命中预览。
6. 预测任务：创建参数、运行进度、错误下载、任务版本。
7. 预测结果：候选列表、计划详情、证据、合并/拆分/调整。
8. 年度计划：主表、明细、审核、发布、导出和执行回填。
9. 模型配置：中转站、模型 ID、密钥引用、连通性测试和调用统计。
10. 系统管理：用户、角色、区域授权、审计日志。

## 13. 非功能要求

- 安全：最小权限、HTTPS、密钥托管、敏感字段脱敏、审计留痕、防越权访问。
- 稳定性：模型服务异常不影响规则预测；异步任务可重试、可恢复、可取消。
- 性能：常规列表查询分页返回；预测任务支持进度查询；大文件导入采用异步处理。
- 一致性：金额、枚举、编码和状态由后端统一校验，前端不能绕过业务规则。
- 可解释性：每条计划至少展示来源项目、历史样本、排除判断、金额方法和时间方法。
- 可维护性：规则、阈值、样本窗口和模型配置均可配置并有版本。
- 兼容性：支持主流桌面浏览器，导入导出兼容常用 Excel 格式。

## 14. 验收标准

- 能创建指定年度预测任务，并正确筛选有效在建项目和新接项目。
- 历史数据能识别首年采购，且名称可映射到标准编码或产生待处理异常。
- 命中股份区域联采中心规则的事项不进入局级计划，并可查看排除原因。
- 一份年度计划支持多个明细条目，条目包含全部必需输出字段。
- 金额、开始时间、完成时间均展示算法来源、样本数和置信度。
- 支持计划条目合并、拆分、人工修改、审核、退回、发布和版本对比。
- 模型配置支持中转站、模型 ID 和密钥安全保存；密钥不出现在前端、日志和导出文件中。
- 大模型不可用、输出格式错误或超时时，系统自动使用规则结果并提示用户。
- 全部关键操作可查询审计记录，预测结果可以追溯到任务和规则版本。
- 发布前的必填、重复、金额、日期和排除冲突校验全部生效。

## 15. 交付阶段建议

### 第一阶段：可用闭环

完成基础数据、历史数据导入、排除规则、规则预测、计划审核发布和 Excel 导出。

### 第二阶段：预测增强

加入相似项目、金额和时间统计优化、大模型归一化、解释和异常检测。

### 第三阶段：持续学习

接入执行结果回填，比较预测与实际偏差，优化项目相似度、金额估算和采购周期参数。

## 16. 待确认事项

1. 新接项目的正式定义、数据来源和生效时间。
2. 局级、本部、下级区域联采的准确枚举和组织边界。
3. 股份区域联采中心排除规则的维护责任部门和优先级。
4. 计划条目的跨项目、跨区域合并口径。
5. 概算金额是否有统一基准单价、项目规模口径或审批阈值。
6. 模型中转站的兼容协议、网络访问范围和密钥托管方式。
7. 用户认证方式、组织架构来源和区域数据权限。
